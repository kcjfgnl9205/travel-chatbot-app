## 1. 호텔 링크가 다른 지역이나 홈으로 연결되는 문제

- **입력** — "오사카 호텔 1박 10만원 이하" 입력 후 결과에 나온 호텔의 Hotels.com 링크 클릭
- **현재** — 추천한 호텔이 아닌 다른 지역이 나오거나, 결과가 없거나, Hotels.com 홈으로 이동. **예산을 넣은 요청의 결과**에서 확인됨
- **원하는 결과** — 추천한 호텔의 링크를 누르면 같은 호텔로 이동해야 한다. 지역 검색 링크라면 오사카 호텔 검색 결과가 나와야 한다
- **수정 요청** — 추천 내용과 실제 연결되는 호텔·지역이 일치하도록 수정. **연결할 수 없는 링크는 정상적인 예약 링크처럼 표시하지 말 것**

## 2. 호텔 정보를 가져오지 못하는 문제

- **입력** — "부산 호텔" / "도쿄 신주쿠 호텔"
- **현재** — 처리 중 안내 후 "호텔 정보를 지금은 정리하지 못했다"는 답변. 신주쿠를 이미 입력했는데도 **동네 이름을 붙여 말하라고 안내**. 부산 호텔은 나중에 다시 테스트했을 때 정상 결과가 나오기도 함 (= 간헐적)
- **원하는 결과** — 입력한 지역의 호텔 목록을 안정적으로 표시. 일시적으로 못 보여주면 **상황에 맞는 재시도 안내**
- **수정 요청** — 부산·신주쿠 호텔 요청의 실패를 수정. 이미 동네를 입력한 경우 동네를 다시 입력하라는 안내가 나오지 않게 할 것

## 3. 상세 지역을 넣은 호텔 요청을 이해하지 못하는 문제

- **입력** — "부산 해운대 호텔" / "@가자고 도쿄 신주쿠 호텔 찾아줘"
- **현재** — "어떤 여행을 찾으시나요?" + 요청을 이해하지 못했다는 답변. **신주쿠 문장은 도움말에 있는 예시를 그대로 입력한 것**
- **원하는 결과** — 해운대·신주쿠의 호텔을 찾는 요청으로 이해하고 해당 지역 호텔을 표시. 도움말 예시는 그대로 입력해도 동작해야 한다
- **수정 요청** — 도시+동네 호텔 요청을 인식하도록 수정. 도움말의 호텔 예시도 실제로 정상 동작하도록 맞출 것

## 4. 자연스러운 관광지 요청을 다시 입력해야 하는 문제

- **입력** — "부산 관광지 추천해줘"
- **현재** — "어떤 여행을 찾으시나요?"라고 되물음. "부산 관광지"라고 짧게 다시 입력하자 추천 결과가 나옴
- **원하는 결과** — 처음 입력한 "부산 관광지 추천해줘"만으로 결과가 나와야 한다
- **수정 요청** — 지역과 원하는 정보가 이미 들어 있는 문장을 이해하도록 수정. 사용자가 같은 뜻을 짧은 단어로 바꿔 다시 입력하지 않아도 되게 할 것

## 5. 지역을 이어서 말해도 대화가 연결되지 않는 문제

- **입력** — 도쿄 관광지 결과를 받은 뒤 "관광지 추천해줘" → 다음 답변 뒤 "제주"만 입력
- **현재** — 이해하지 못했다는 안내가 반복. "제주 관광지"라고 전체를 다시 입력한 뒤에야 결과. **다른 테스트에서는 같은 "관광지 추천해줘"에 어느 지역인지 정상적으로 되묻기도 함** (= 동작이 일정하지 않음)
- **원하는 결과** — 지역이 없으면 "어느 지역 관광지를 찾으세요?"라고 묻고, "제주"라고 답하면 제주 관광지를 표시
- **수정 요청** — 부족한 정보만 물어보고, 이어서 입력한 지역을 앞선 요청과 연결. 같은 요청에 안내가 달라지거나 이해 실패가 반복되지 않게 할 것

## 6. 귀국일이 출발일보다 빠르면 날짜를 바꾸는 문제

- **입력** — "서울에서 도쿄 항공권 11월 23일 출발 11월 20일 귀국"
- **현재** — "11월 23일 출발 · 11월 30일 귀국 · 1인"으로 안내. 입력한 귀국일 11월 20일이 **설명이나 확인 없이 11월 30일로 변경**됨
- **원하는 결과** — 귀국일이 출발일보다 빠르다는 점을 알려주고 올바른 귀국일을 다시 입력하게 해야 한다
- **수정 요청** — 잘못된 날짜를 임의의 날짜로 바꾸지 말 것. 사용자가 날짜를 수정하거나 변경에 동의한 뒤에 항공권 링크를 제공할 것

## 7. 명시한 과거 연도를 다음 해로 바꾸는 문제

- **입력** — "서울에서 도쿄 항공권 2026년 10월 20일 출발 2026년 10월 23일 귀국"
- **현재** — 2026년을 명시했는데 **2027년 10월** 날짜로 안내. 테스트일(2026-10-31) 기준 입력한 날짜는 이미 지난 날짜
- **원하는 결과** — 입력한 날짜가 과거임을 알려주고 새 날짜를 요청. 사용자가 적은 연도를 다른 연도로 바꾸면 안 된다
- **수정 요청** — 연도가 적힌 요청은 그 연도를 기준으로 확인. 지난 날짜면 다음 해로 바꾸지 말고 다시 입력하도록 수정

## 8. 호텔 날짜와 예산 안내가 도움말과 맞지 않는 문제

- **입력** — "오사카 호텔 1박 10만원 이하" / "오사카 호텔 2026년 11월 20일 체크인 11월 23일 체크아웃"
- **현재** — 각각 "날짜·예산(1박, 10만원)은 반영되지 않았어요.", "날짜(11월 20일, 11월 23일)은 반영되지 않았어요." 안내. 반면 **도움말에서는 더 정확한 결과를 위해 날짜·인원·예산을 함께 알려달라고 안내**하고 있음
- **원하는 결과** — 지원하는 조건은 요청대로 반영. 호텔 날짜·예산을 지원하지 않는다면 도움말에서도 그 범위를 분명히 알려야 한다
- **수정 요청** — 호텔에서 지원하는 조건을 확인한 뒤 **도움말과 실제 결과 안내를 일치**시킬 것. 지원 조건은 결과에 반영하고, 미지원 조건은 입력 전에도 알 수 있게 안내. **"1박"은 날짜가 아니라 가격 기준으로 구분**할 것

## 9. 제휴 관련 안내가 보이지 않는 문제

- **상황** — 호텔·항공권 결과에서 광고·제휴·수수료 관련 안내가 있는지 확인
- **현재** — 화면에 관련 안내 문구가 보이지 않음
- **원하는 결과** — 제휴 안내가 필요한 링크라면 사용자가 **누르기 전에** 그 내용을 알 수 있어야 한다
- **수정 요청** — 각 링크에 제휴 안내가 필요한지 먼저 확인하고, 필요한 경우 실제 제휴 관계에 맞는 문구를 결과 화면의 알아보기 쉬운 위치에 추가

## 10. 입력 상황에 맞지 않는 공통 안내 문제

- **입력** — "없는도시123 관광지" / "파이썬으로 계산기 코드 만들어줘"
- **현재** — 두 요청 모두 어떤 여행을 찾는지 묻고 이해하지 못했다는 안내. 코드 요청에서는 "아래 예시를 참고해"라고 했지만 화면에는 **예시 대신 도움말 버튼**. "못했어" 다음 줄에 "요."만 나오는 **줄바꿈 깨짐**도 발견
- **원하는 결과** — 없는 지역명에는 지역명을 다시 확인해 달라고, 여행 외 요청에는 관광지·호텔·항공권을 도와주는 서비스라고 안내. 화면의 문구와 버튼이 서로 맞아야 한다
- **수정 요청** — 상황에 맞는 안내로 변경. 예시를 직접 보여주지 않는다면 도움말 버튼에서 확인하라고 안내하고, 문장이 어색하게 끊어지지 않도록 줄바꿈 정리
