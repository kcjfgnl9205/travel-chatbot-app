# 관광지 검색 — 발화에서 말풍선까지

> "오사카 관광지 추천해줘" 한 줄이 들어와서 `listCard` 다섯 줄이 나가기까지.
> 라우터 공통 구조는 [ROUTER.md](./ROUTER.md), 호텔·항공권은 [HOTEL.md](./HOTEL.md) · [FLIGHT.md](./FLIGHT.md).

**호텔·항공권과 결정적으로 다른 점 둘.**

**① 목록이 우리 DB 에 있다.** 구글 Places 도 위키미디어도 안 부른다. 모델은 **아무도 안 넣은 도시**에서만 나서고, 그때도 사용자에게 바로 가는 게 아니라 DB 에 먼저 들어간다 (9절).

**② 제휴 링크 단계가 통째로 없다.** 관광지는 우리가 파는 게 아니라 장소다. 예약 페이지가 없으니 애드픽에 변환할 주소도 없고, 그래서 rate limit 도 변환 실패 폴백도 없다. 링크는 **이름 + 도시로 우리가 만든 구글맵 주소**다.

그래서 **목록이 있는 도시는 응답이 한 번에 나간다.** "찾고 있어요" 도 콜백 대기도 없다. 빈 도시만 예전처럼 대기 → 콜백을 탄다.

> **0009 이전과 완전히 다르다.** 예전에는 구글이 목록을 주고 모델이 순서를 정하고 위키미디어가 사진을 붙였다. 왜 걷어냈는지는 [10절](#10-왜-외부-api-를-걷어냈나)에 있다.

## 1. 어떤 발화가 관광지로 오나

### 키워드

```
관광 · 명소 · 가볼 · 볼거리 · 놀거리 · 맛집 · 구경 · 여행지
```

**호텔 → 항공권 → 관광지 순으로 본다.** 셋 다 걸리면 호텔이 이긴다.

### 판정은 3단계

| 단계 | 무엇 | 모델 호출 | 예시 |
|---|---|---|---|
| ① 대표 명령어 | `/여행지 오사카` · `관광지 오사카` · `맛집 오사카` | **0회** | |
| ② 키워드 + 도시 사전 | 관광 키워드 + 237개 도시표 | **0회** | "오사카 관광지 추천해줘" |
| ③ 모델 | 위 둘로 안 되면 gpt-5-mini | 1회 | "도톤보리 근처 볼거리" |

대표 명령어는 `여행지` · `관광지` · `맛집` 셋 다 관광지로 매핑된다.

### 발화별 파싱 결과

| 발화 | place | 경로 |
|---|---|---|
| `오사카 관광지 추천해줘` | 오사카 | ② |
| `오사카 가볼 만한 곳` | 오사카 | ② |
| `여행지 도톤보리` | 도톤보리 | ① |
| `오사카 맛집 알려줘` | 오사카 | ② |
| `베트남 여행지` | 베트남 | ② → **도시 되묻기** |

### ⚠️ 맛집도 여기로 온다

`맛집` 키워드는 관광지로 매핑되지만, **검색 프롬프트는 "맛집"을 따로 다루지 않는다.** 일반 관광지를 찾고 그중 `음식/시장` 카테고리가 섞여 나올 뿐이다. 맛집만 원하는 사용자에게는 기대와 다른 결과다 — 알려진 한계(10절).

### ⚠️ 테마는 아직 파싱하지 않는다

"아이랑 갈 만한", "야경 좋은" 같은 조건은 뽑지도, 고지하지도 않는다. 날짜·인원처럼 `ignored` 에 담기지도 않아서 **사용자는 반영된 줄 안다.** 이것도 한계다.

## 2. 발화 → 응답 전체 흐름

경로가 둘이다. **DB 에 목록이 있느냐**로 갈린다.

### 목록이 있다 — 즉시 (대부분)

```
"@여행메이트 오사카 관광지 추천해줘"
  │  ── 카카오 5초 예산 안. 전부 여기서 끝난다 ──────────
  ├─ 의도·지명 추출            → intent=attraction, place=오사카
  ├─ 지역 정규화               "오사카" → place_id=42
  ├─ peek(): attractions 조회  where city_id=42 order by rank, name
  ├─ 지도 링크 · 중복 제거
  ├─ search_results 에 저장    "더 보기" 가 여기서 페이지를 자른다
  └─ listCard 즉시 반환 ✅
```

### 목록이 없다 — 모델이 채운다 (도시당 한 번)

```
  ├─ peek() → 빈손 → null 반환   "즉시 못 정한다"
  ├─ pending 선점
  ├─ "오사카 관광지를 찾고 있어요 🔍"   ← 사용자에게 먼저 나간다
  │  ── 백그라운드 ──────────────────────────────────
  ├─ 모델 1회                    관광지 20곳 (웹 검색 없음)
  ├─ attractions 에 insert       source='ai'
  ├─ 다시 조회                   ⚠️ DB 가 정본이다
  └─ 카드 조립 → callbackUrl 로 POST
```

**두 번째 사람부터는 위쪽 경로다.** 모델은 도시당 한 번만 부른다.

[`SearchDomain.peek()`](../src/modules/search/search.types.ts) 이 이 갈림길이다 — 목록을 주면 즉시, `null` 을 주면 느린 경로, `[]` 면 "더 해볼 것 없음"이다.

## 3. 상황별로 무엇이 나가나

| 상황 | 실제 문구 |
|---|---|
| 목록이 있다 | **카드 즉시** |
| 빈 도시 + 백필 켜짐 | `오사카 관광지를 찾고 있어요. 잠시만요 🔍` → 콜백으로 카드 |
| 빈 도시 + 백필 꺼짐 | `오사카 관광지 정보를 지금은 정리하지 못했어요 🙏` |
| 모델까지 실패 | 같은 문구 (다음 질문에 다시 시도한다) |
| DB 가 아예 없다 | `지금은 오사카 관광지 검색이 안 되고 있어요 🙏` |
| 나라를 말함 | `베트남 어느 도시의 관광지를 찾을까요?` |

> `관광지` 는 받침이 없어 조사가 `를` 다. 문구를 `${...}을` 로 박아두면 **"관광지을 찾으세요?"** 가 나간다 — 실제로 나갔다. [`withObjectParticle()`](../src/modules/kakao/cards.ts) 이 음절 코드로 받침을 판정한다.

## 4. 카드 한 장 해부

```json
{
  "listCard": {
    "header": { "title": "오사카 관광지 12곳" },
    "items": [
      {
        "title": "오사카성",
        "description": "주오구",
        "imageUrl": "https://cdn.example.com/osaka-castle.jpg",
        "link": { "web": "https://bot.nolmoa.com/r/abc123" }
      }
    ],
    "buttons": [{ "label": "더 보기", "action": "block", "…": "…" }]
  }
}
```

### 한 줄 설명이 위치 하나로 줄었다

이 자리는 계속 줄어들었다.

| 시기 | 한 줄 | 왜 빠졌나 |
|---|---|---|
| ~0007 | `무료 · 2시간 · 역사/문화 · 주오구` | 입장료·소요시간을 모델이 지어냈다 |
| 0008 | `★ 4.4 (61,234) · 역사/문화 · 주오구` | — |
| **0009** | **`주오구`** | 평점·카테고리가 구글 콘텐츠였다 (10절) |

빈 값이면 설명 없이 제목만 나간다. [`listDescription()`](../src/modules/attraction/attraction-card.ts) 이 전부다.

> 다시 채우고 싶으면 **`attractions` 테이블부터**다. 카드에 찍을 값은 전부 DB 에 있어야 한다는 게 이 판의 규칙이다.

## 5. ⚠️ 입장료·소요시간을 모으지 않는다

칸 자체가 없다. 구글도 안 주고 모델은 지어낸다 — **틀린 가격은 없는 가격보다 나쁘다.** 0008 에서 `admission_fee` · `admission_currency` · `duration_minutes` · `free` · `description` 을 통째로 드롭했다.

넣고 싶으면 사람이 채우는 칸으로 되살리면 된다. 그게 0009 의 방식이다.

## 6. 링크를 우리가 만든다

```
https://www.google.com/maps/search/?api=1&query=오사카성%20오사카
```

[`mapsUrl()`](../src/common/maps-url.ts) 이 이름+도시로 만든다. 모델이 준 게 아니라 규약에 이름을 끼운 것이라 **지어낼 자리가 없다.**

> 0008 까지는 `&query_place_id=ChIJ…` 를 붙여 그 장소를 정확히 열었다. 구글을 끊으면서 place_id 를 안 받으므로 이름 검색으로 돌아갔다. 도시명을 붙이니 실사용에서 거의 정확히 찍힌다.

### 그래도 `/r/{clickId}` 를 거친다

수수료가 없어도 **어떤 관광지를 눌렀는지**는 알아야 다음 목록이 나아진다. 카카오 링크는 브라우저를 바로 열어서, 한 홉을 끼우지 않으면 아무 신호도 오지 않는다.

`links` 를 렌더러에 **안 넘긴다** — 그게 이 도메인의 표식이다. 빈 Map 은 "변환을 시도했는데 하나도 못 건졌다"(수익 누수)라 경고가 뜨는데, `undefined` 는 "변환을 다루지 않는 도메인"이다.

## 7. 사진 — 관리 화면에서 넣는다

`attractions.image_url` 에 주소를 직접 넣는다. 찾아오는 코드가 없다.

> ⚠️ **https 여야 한다.** 카카오는 http 이미지를 조용히 안 그린다. 관리 API 가 등록 시점에 막는다 — 통과시키면 운영자는 카드를 보고서야 안다.

**없어도 된다.** 그 줄만 사진 없이 나가고, 목록에서 빼지는 않는다 — 추천 자체가 사라지는 게 사진 한 장 없는 것보다 나쁘다.

어디서 구한 사진을 넣을지는 **운영의 판단이고 법적 책임도 거기 붙는다.** 자유 라이선스(위키미디어 커먼즈 · Unsplash · Pexels)이거나 직접 촬영한 것이 안전하다. 웹에서 찾은 아무 사진은 출처를 적어도 쓸 권리가 생기지 않는다.

## 8. 결과는 어떻게 만들어지나

```
1차  우리 DB      목록 · 이름 · 위치 · 사진 · 순서     쿼리 1회
2차  우리         지도 링크                            무료
```

빈 도시일 때만 0차가 붙는다: **모델이 20곳을 제안 → DB insert → 1차로 돌아간다.**

### 역할이 갈린다

| | 맡는 것 |
|---|---|
| **사람** | 무엇을 보여줄지 · 어떤 순서로 · 어떤 사진으로 |
| **코드** | 지도 링크 · 중복 제거 · 페이지 자르기 |
| **모델** | **빈 도시의 초안만.** 사진은 안 만든다 |

### 백필 — 빈 도시를 모델이 채운다

[`attraction-backfill.ts`](../src/modules/attraction/attraction-backfill.ts).

> ⚠️ **`b87194a` 에서 되돌렸던 구조와 한 끗 차이다.** 그때는 모델 출력이 사용자에게 **바로** 갔다. 폐관한 곳이 섞여도 DB 에 안 남으니 아무도 모르고, 다음 사람에게 또 같은 거짓말이 나갔다.
>
> 지금은 DB 를 거친다. 그 차이가 셋이다 —
> - **도시당 한 번**만 부른다 (백 명이 물어도 모델은 1회)
> - `source='ai'` 로 표시돼 **나중에 훑어 고칠 수 있다**
> - 관리 화면에서 한 줄만 지우면 끝난다

지키는 것들:

| | |
|---|---|
| **사람이 넣은 것을 안 덮는다** | 부르기 직전에 DB 를 다시 본다. 비어 있을 때만 채운다 |
| **같은 도시를 두 번 안 산다** | 프로세스 안 잠금 + 검색 쪽 pending 선점, 두 겹 |
| **사진을 안 만든다** | 모델은 CDN 주소를 지어낸다 (호텔에서 확인된 것) |
| **웹 검색을 안 쓴다** | `web_search` 는 도시당 $0.05~0.1. 학습 지식만 쓰면 $0.002 |
| **표기 중복을 먼저 접는다** | '오사카성' 과 '오사카 성' 이 같이 오면 유니크 인덱스에 걸려 **insert 배열 전체가 실패**한다 |

⚠️ **최근에 생긴 곳은 모른다.** 웹 검색을 안 쓰는 대가다.

### 순서 — `rank`, 같으면 이름

```sql
order by rank, name
```

`rank` 만으로 정렬하면 같은 값끼리 순서가 흔들려서, 사용자가 다시 물었을 때 목록이 뒤바뀐 것처럼 보인다. 이름을 2차 기준으로 둬서 **매번 같은 순서**를 보장한다.

### 중복 제거 — `attractions.id` 기준

이름으로 판정하면 관리 화면에서 표기를 고치는 순간 다른 곳이 된다. DB 에 `unique (city_id, name)` 이 걸려 있어 사실상 겹칠 일이 없지만, 캐시에서 되살린 목록에도 걸리도록 한 겹 더 둔다.

## 9. DB · 관리 API · 설정

### 테이블

```sql
attractions
  id         bigserial primary key
  city_id    → places(id)      어느 도시인가. 조회의 유일한 열쇠
  name       text not null     카드 제목
  area       text              주오구 · 우메다. 카드 설명 한 줄
  image_url  text              https 여야 한다
  rank       integer           0이 첫째
  unique (city_id, name)       같은 이름을 두 번 못 넣는다
```

**보관 기간 제한이 없다.** 우리가 넣은 것이라 30일 캐시로 나눠 담을 이유가 사라졌다 — 0008 의 `attraction_places` / `search_results` 2층 구조가 통째로 없어진 이유다.

### 관리 API

전부 `X-Debug-Token` 으로 보호된다. `DEBUG_TOKEN` 이 비어 있으면 **404** 다.

| | |
|---|---|
| `GET /api/v1/admin/attractions?city=오사카` | 목록 (카드와 같은 순서) |
| `GET …?city=오사카&source=ai` | **모델이 채운 것만** — 검수용 |
| `POST /api/v1/admin/attractions` | 등록 |
| `PATCH /api/v1/admin/attractions/:id` | 수정 (**준 칸만**) |
| `DELETE /api/v1/admin/attractions/:id` | 삭제 |
| `POST /api/v1/admin/attractions/reorder` | 순서 (`ids` 배열 위치가 곧 rank) |

```bash
curl -s localhost:8000/api/v1/admin/attractions \
  -H 'content-type: application/json' -H "X-Debug-Token: $DEBUG_TOKEN" \
  -d '{"city":"오사카","name":"오사카성","area":"주오구","imageUrl":"https://cdn/a.jpg","rank":0}'
```

> ⚠️ **PATCH 는 `undefined` 와 `null` 이 다르다.** 안 주면 그대로 두고, `null` 을 주면 비운다. 한데 묶으면 이름만 고치려던 요청이 사진을 지운다.

도시 행을 미리 심어두려면 한 번만: `POST /api/v1/catalog/seed` (사전 112곳, 모델 안 부름).

### 노출 스냅샷

`recommendation_item_attractions` 에 `attraction_id` · `area` · `image_url` 이 남는다. 관광지를 지워도 **기록은 남는다** (`on delete set null`) — 이름은 `recommendation_items.label` 에 있다.

### 캐시

**읽지 않는다.** 질문마다 DB 를 본다. `search_results` 에 쓰기는 하는데 **"더 보기"가 그 행에서 다음 페이지를 자르기** 때문이지 캐시로 쓰려는 게 아니다. `ATTRACTION_CACHE_TTL_MINUTES` 기본값이 43200(30일)에서 **60** 으로 내려간 이유다.

### 설정

| 변수 | 기본 | 설명 |
|---|---|---|
| `ATTRACTION_CACHE_TTL_MINUTES` | `60` | 페이지네이션 행의 수명 |
| `ATTRACTION_BACKFILL` | `true` | 빈 도시를 모델이 채울지. 끄면 빈 채로 남는다 |
| `ATTRACTION_BACKFILL_COUNT` | `20` | 한 도시에 몇 곳을 채울지 |
| `DEBUG_TOKEN` | — | **비면 관리 API 가 404** |

**이게 전부다.** `GOOGLE_PLACES_API_KEY` · `GOOGLE_PLACES_TIMEOUT_SECONDS` · `ATTRACTION_IMAGES` · `ATTRACTION_IMAGE_TIMEOUT_SECONDS` · `ATTRACTION_REFRESH_DAYS` 는 0009 에서 전부 사라졌다.

## 10. 왜 외부 API 를 걷어냈나

0008 의 구조(구글 목록 + 모델 순서 + 위키미디어 사진)는 잘 돌았다. 걷어낸 건 품질이 아니라 **빌려 쓰는 값**이었다.

### ① 요금 — 무료 한도가 월 1,000회였다

카드의 `★ 4.4 (61,234)` 한 줄 때문에 `places.rating` 을 요청했는데, 구글은 **"요청에 걸린 가장 높은 SKU"** 로 과금한다. 그 한 칸이 전체 호출을 **Text Search Enterprise** 로 올렸다.

| SKU | 월 무료 |
|---|---|
| Essentials | ~10,000회 |
| Pro | ~5,000회 |
| **Enterprise** | **~1,000회** |

도시 하나에 타입별 6회가 나갔다. 배치만 돌아도 월 720회로 한도의 70% 였고, 사용자가 캐시에 없는 도시를 물을 때마다 6회씩 더 나갔다.

### ② 약관 — 보관도 표시도 제약이 있었다

- `place_id` 외의 콘텐츠는 **장기 보관이 제한**된다 → 이름·평점을 30일 캐시에만 두고 만료되면 실제로 지워야 했다
- 지도 없이 Places 콘텐츠를 보여주면 **출처를 밝혀야 한다** ("Google Maps", 같은 말풍선 안) → **밝히지 않고 있었다**

### ③ 저작권 — 사진 출처를 달 자리가 없었다

위키미디어 사진은 대부분 저작자 표시가 필요한데, `listCard` 한 줄에는 링크가 하나뿐이고 그 자리는 지도가 쓴다. 게다가 저작자·라이선스 정보를 **받아오지도 않고 있었다** (`piprop=thumbnail` 만 요청).

### 대가 — 그리고 백필이 그걸 메운다

커버리지가 문제였다. 도시 237곳을 손으로 채우는 건 현실적이지 않다. 그래서 **빈 도시는 모델이 채우되, DB 를 거치게** 했다 (8절).

남는 위험은 하나다 — **모델이 폐관한 곳을 그럴듯하게 섞는다.** 예전과 다른 건 이제 그게 어디 있는지 알 수 있다는 것이다 (`source='ai'`).

얻은 것 — 구글 요금 0원, 약관 제약 0, 출처 표시 의무 0, 목록 있는 도시는 1초 미만 + 콜백 없음, 그리고 **무엇이 나갈지 우리가 고칠 수 있다.**

## 12. 알려진 한계

- **모델이 채운 행은 검증되지 않았다.** 폐관한 곳·없는 곳이 섞일 수 있다. `GET …?source=ai` 로 훑어보는 것이 전제다
- **최근에 생긴 곳은 모델이 모른다.** 웹 검색을 안 쓰는 대가 — 그런 곳은 사람이 넣어야 한다
- **사진은 백필이 안 채운다.** 모델이 채운 도시는 전부 사진 없는 줄이다
- **맛집을 따로 다루지 않는다** (1절). `맛집` 발화도 같은 목록으로 간다
- **테마를 파싱하지 않는다** — "아이랑", "야경" 은 뽑지도 고지하지도 않아서 사용자는 반영된 줄 안다
- **영업시간·휴무일이 없다.** 폐관한 곳은 운영이 지워야 한다 (예전에는 구글이 걸러줬다)
- **세부 지역(도톤보리)** 은 `places` 에 행이 생기지만, 거기에 관광지를 따로 넣지 않으면 빈손이다
- 관리 화면은 이 저장소에 없다. API 만 있다
