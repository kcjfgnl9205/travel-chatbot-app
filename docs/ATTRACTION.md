# 관광지 검색 — 발화에서 말풍선까지

> "오사카 관광지 추천해줘" 한 줄이 들어와서 `listCard` 다섯 줄이 나가기까지.
> 라우터 공통 구조는 [ROUTER.md](./ROUTER.md), 호텔·항공권은 [HOTEL.md](./HOTEL.md) · [FLIGHT.md](./FLIGHT.md).

**호텔·항공권과 결정적으로 다른 점 하나: 제휴 링크 단계가 통째로 없다.**

관광지는 우리가 파는 게 아니라 장소다. 예약 페이지가 없으니 애드픽에 변환할 주소도 없고, 그래서 rate limit 도 변환 실패 폴백도 없다. 링크는 **이름 + 도시로 우리가 만든 구글맵 주소**다.

이게 이 도메인에서 가장 큰 단순화다. 모델에게 URL 을 안 받으므로
- 허용 호스트 목록이 없고
- 링크가 죽었는지 확인할 일이 없고
- 모델이 지어낸 주소로 사용자가 404 를 보는 일도 없다

---

## 1. 어떤 발화가 관광지로 오나

### 키워드

```
관광 · 명소 · 가볼 · 볼거리 · 놀거리 · 맛집 · 구경 · 여행지
```

**호텔 → 항공권 → 관광지 순으로 본다.** 셋 다 걸리면 호텔이 이긴다.

### 판정은 3단계

| 단계 | 무엇 | 모델 호출 | 예시 |
|---|---|---|---|
| ① 대표 명령어 | `/여행지 오사카` · `관광지 오사카` · `맛집 오사카` | **0회** | |
| ② 키워드 + 도시 사전 | 관광 키워드 + 237개 도시표 | **0회** | "오사카 관광지 추천해줘" |
| ③ 모델 | 위 둘로 안 되면 gpt-5-mini | 1회 | "도톤보리 근처 볼거리" |

대표 명령어는 `여행지` · `관광지` · `맛집` 셋 다 관광지로 매핑된다.

### 발화별 파싱 결과

| 발화 | place | 경로 |
|---|---|---|
| `오사카 관광지 추천해줘` | 오사카 | ② |
| `오사카 가볼 만한 곳` | 오사카 | ② |
| `여행지 도톤보리` | 도톤보리 | ① |
| `오사카 맛집 알려줘` | 오사카 | ② |
| `베트남 여행지` | 베트남 | ② → **도시 되묻기** |

### ⚠️ 맛집도 여기로 온다

`맛집` 키워드는 관광지로 매핑되지만, **검색 프롬프트는 "맛집"을 따로 다루지 않는다.** 일반 관광지를 찾고 그중 `음식/시장` 카테고리가 섞여 나올 뿐이다. 맛집만 원하는 사용자에게는 기대와 다른 결과다 — 알려진 한계(10절).

### ⚠️ 테마는 아직 파싱하지 않는다

"아이랑 갈 만한", "야경 좋은" 같은 조건은 뽑지도, 고지하지도 않는다. 날짜·인원처럼 `ignored` 에 담기지도 않아서 **사용자는 반영된 줄 안다.** 이것도 한계다.

## 2. 발화 → 응답 전체 흐름

```
"@여행메이트 오사카 관광지 추천해줘"
  │
  │  ── 카카오 5초 예산 안 ─────────────────────────────
  │
  ├─ 의도·지명 추출            → intent=attraction, place=오사카
  ├─ 지역 정규화               "오사카" → place_id=42
  ├─ 캐시 조회                 attraction:42
  │    ├ 히트 → listCard 즉시 ✅
  │    └ 미스 → pending 선점 → 아래로
  │
  │  ── 백그라운드 ────────────────────────────────────
  │
  ├─ provider 검색             gpt-5-mini 2단 + 웹 검색 (7~30초)
  ├─ 지도 링크 생성            이름+도시 → maps-url.ts    ← 모델이 아니라 우리가
  ├─ 중복 제거                 mapUrl 기준
  ├─ 사진 확보                 위키백과 ko → en           (모델 아님)
  ├─ search_results 에 20건 저장 (TTL 30일)
  └─ 카드 조립 → callbackUrl 로 POST
```

## 3. 상황별로 무엇이 나가나

호텔·항공권과 같다. 주어만 `오사카 관광지` 로 바뀐다.

| 상황 | 실제 문구 |
|---|---|
| 미스 + 콜백 켜짐 | `오사카 관광지를 찾고 있어요. 잠시만요 🔍` |
| 미스 + 콜백 꺼짐 | `오사카 관광지를 찾고 있어요 🔍`<br>`30초쯤 뒤에 다시 물어봐 주세요!` |
| 남이 검색 중 | `오사카 관광지를 먼저 찾고 있어요 🔍` |
| 결과 0건 | `오사카 관광지 정보를 지금은 정리하지 못했어요 🙏` |
| 검색 실패 | `오사카 관광지를 불러오지 못했어요 🙏` |
| 키가 없어 불가 | `지금은 오사카 관광지 검색이 안 되고 있어요 🙏` |
| 나라를 말함 | `베트남 어느 도시의 관광지를 찾을까요?` |

> `관광지` 는 받침이 없어 조사가 `를` 다. 문구를 `${...}을` 로 박아두면 **"관광지을 찾으세요?"** 가 나간다 — 실제로 나갔다. [`withObjectParticle()`](../src/modules/kakao/cards.ts) 이 음절 코드로 받침을 판정한다.

```json
  "template": {

          "header": { "title": "오사카 관광지 5곳" },
          "items": [

              "description": "1,200엔 · 1시간 30분 · 주오구",
              "imageUrl": "https://upload.wikimedia.org/....jpg",
              "link": { "web": "https://bot.nolmoa.com/r/Rt4nP8wLc1Yj" } }
          ],
          "buttons": [
            { "label": "더 보기", "action": "block", "blockId": "...",
              "messageText": "오사카 관광지 더 보기",
              "extra": { "cache_key": "attraction:42", "offset": 5 } }
          ] } }
    ],
    "quickReplies": [
      { "label": "도쿄 관광지", "action": "message", "messageText": "도쿄 관광지 추천해줘" },
      { "label": "후쿠오카 관광지", "action": "message", "messageText": "후쿠오카 관광지 추천해줘" }
    ]
  }

```

**고지 말풍선이 대개 없다.** 관광지는 날짜·인원을 쓰지 않으므로 버릴 조건도 없다. 사용자가 "9월에 오사카 관광지" 라고 하면 그때만 고지가 붙는다.

### 머리글

| 페이지 | 문구 |
|---|---|
| 1페이지 | `오사카 관광지 5곳` |
| 2페이지부터 | `오사카 관광지 6~10번째` |

### 한 줄의 제목·설명

```
title        관광지 이름                  (40자, 2줄)
description  입장료 · 소요시간 · 위치      (40자, 1줄)
imageUrl     위키백과 사진 (없을 수 있다)
link.web     /r/{clickId} → 302 → 구글맵
```

[`listDescription()`](../src/modules/attraction/attraction-card.ts) 의 우선순위는 **입장료 → 소요 시간 → 위치**(없으면 카테고리)다.

> **한 줄 소개(description)를 카드에 안 넣는다.** 소개는 40자에서 잘려 문장이 끊기는데, 그러면 세 조각 다 못 보여주고 잘린 문장만 남는다. 소개는 DB 에만 남긴다.

### 입장료 표기

| 상황 | 표기 |
|---|---|
| 무료 | `무료` |
| 금액 + 통화 | `1,200엔` · `250바트` · `1,200 MYR`(모르는 통화) |
| 유료인 건 알지만 금액 모름 | `유료` |
| 아무것도 모름 | 생략 |

`유료` 는 정보가 적어 보이지만, "돈을 내야 하는 곳"이라는 건 일정을 짤 때 알아야 하는 사실이다.

## 5. ⚠️ 입장료를 원화로 환산시키지 않는다

이 도메인에서 가장 중요한 규칙이다.

환산을 시켜봤더니 **1,200엔짜리 오사카성이 `5,760원`, 2,700엔짜리 카이유칸이 `2,700원`** 으로 나왔다. 환율을 모른 채 현지 통화 숫자를 원화 칸에 그대로 넣거나 엉뚱하게 곱한 결과다.

**틀린 가격은 없는 가격보다 나쁘다.** 2,700원인 줄 알고 갔다가 27,000원을 낸다.

그래서 프롬프트가 못 박는다:

```
입장료는 성인 1인 기준을 현지 통화 그대로 적고 통화 코드(JPY, THB …)를 함께 낸다.
**원화로 환산하지 마라.** 환율 계산을 하지 말고 검색 결과에 적힌 숫자를 그대로 옮긴다.
```

검색 결과에 적힌 숫자를 옮기는 건 모델이 잘한다. 환율 계산은 못한다.

**통화를 모르면 금액도 버린다.** `1,200` 만 보여주면 원인지 엔인지 알 수 없고, 한국인은 대개 원으로 읽는다 — 그게 정확히 막으려는 오해다.

통화는 ISO 4217 코드만 받는다(enum). 자유 문자열로 두면 모델이 `엔`·`¥`·`yen` 을 섞어 준다.

## 6. 링크를 우리가 만든다

```ts
mapUrl = mapsUrl(관광지명, 도시명)
// https://www.google.com/maps/search/?api=1&query=오사카성%20오사카
```

모델에게 URL 을 묻지 않는다. 호텔에서 확인했듯 모델은 그럴듯한 주소를 지어내고, 그건 카드에 깨진 자리만 남긴다.

**도시명을 붙이는 이유** — "시청" 같은 이름은 전 세계에 있다. 도시를 붙이면 구글맵이 그 도시 안에서 찾는다.

### 그래도 `/r/{clickId}` 를 거친다

수수료가 없는데도 리다이렉트를 한 홉 끼운다. **어떤 관광지를 눌렀는지는 알아야 다음 추천이 나아지기** 때문이다. 카카오 링크는 브라우저를 바로 열어서, 한 홉이 없으면 아무 신호도 오지 않는다.

그래서 코드상 차이는 이렇다:

| | 호텔·항공권 | 관광지 |
|---|---|---|
| 애드픽 변환 | ✅ | ❌ |
| `affiliate_link_id` | 있음 | `null` |
| subid 파라미터 | 붙임 | **안 붙임** |
| 변환 실패 경고 | 있음 | 없음 |
| `/r/{clickId}` | ✅ | ✅ |

공유 렌더러([`RecommendationRowsService`](../src/modules/recommendation/rows.service.ts))는 `links` 를 **안 받으면** "변환을 다루지 않는 도메인"으로 알아서 처리한다. 빈 `Map` 과는 뜻이 다르다 — 빈 Map 은 "변환을 시도했는데 못 건졌다"라 경고 대상이다.

> `AttractionModule` 이 `AffiliateModule` 을 import 하지 않는다. 이 차이가 모듈 그래프에 그대로 보이는 게 맞다.

## 7. 사진 — 위키백과에서 찾는다

```
① 한국어판 검색   이름 + 도시명
② 영어판 검색     nameEn + 도시 슬러그      ← 한국어 문서가 없을 때
③ 못 찾으면 null  그 줄만 사진 없이 나간다
```

호텔은 예약 페이지에서 og:image 를 긁었지만, 관광지는 **긁어올 페이지 자체가 없다.** 위키백과 API 는 구조화된 이미지 주소를 주므로 모델이 지어낼 자리가 없다 — 지도 링크를 우리가 만드는 것과 같은 이유다.

### 영문명을 따로 받는 이유

실측 커버리지 (도시 8곳 × 5곳 = 40곳):

| 언어 | 커버리지 | 비고 |
|---|---|---|
| ko 만 | 62% | 일본·유럽 100%, 동남아 0~40% |
| ko → en | **87%** | 한국어 문서가 없는 동남아를 영문명이 메운다 |

그래서 `name_en` 을 모델에게 같이 받는다. 카드에는 안 쓰이고 **위키백과 검색어로만** 쓴다. 모르면 지어내지 말고 `null` 로 두라고 시킨다.

어느 언어판에서 건졌는지는 로그에 남는다 — `image ko attraction=오사카성 doc=...`. ko/en 비율이 영문명의 값어치를 보여준다.

> 위키미디어는 봇에 연락처가 담긴 User-Agent 를 요구한다. 익명 UA 로 두들기면 차단된다.

> ⚠️ **저작권.** 위키미디어 사진은 대부분 CC BY-SA 라 엄밀히는 저작자 표시가 필요하다. `listCard` 한 줄에는 링크가 하나뿐이고 그 자리는 지도가 써야 해서(클릭 추적) 줄마다 출처를 달 자리가 없다.

## 8. 결과는 어떻게 만들어지나

[`OpenAiAttractionProvider`](../src/modules/attraction/providers/openai.provider.ts) — 2단 구조. 뼈대는 [`TwoStageSearch`](../src/modules/openai/two-stage.ts) 를 공유한다.

```
1차  web_search 로 후보 30곳 수집             (구조화 JSON)
2차  유명세·특색·카테고리를 섞어 20곳 선정      (구조화 JSON)
3차  위키백과에서 사진 (동시에)
```

**2차가 하는 일이 하나 더 있다 — 카테고리를 섞는 것.** 그냥 두면 신사 다섯 곳, 전망대 다섯 곳이 나온다.

```
역사/문화 · 자연/공원 · 테마파크 · 거리/쇼핑 · 전망 · 미술관/박물관 · 음식/시장 · 체험
```

### ⚠️ 이름은 두 가지를 동시에 만족해야 한다

이 도메인에서 이름은 **카드에 찍히는 글자이자 곧 지도 검색어**다. 한쪽만 시키면 다른 쪽이 무너진다.

| 시킨 것 | 나온 것 | 문제 |
|---|---|---|
| "공식 명칭만" | `Umeda Sky Building Kuchu Teien Observatory` | 카드에서 잘림 |
| "한국어로" | `오사카 과학관/가족 체험 공간` | 설명이 붙어 지도 검색 실패 |

그래서 둘 다 명시한다 — 한국어 표기 · 장소 이름만 · 20자 이내 · 설명/영문 병기/슬래시 금지.

프롬프트로 시켜도 모델은 설명을 붙이므로, [`placeName()`](../src/modules/attraction/providers/openai.provider.ts) 이 한 번 더 다듬는다(슬래시 뒤 버리기, 끝의 괄호 설명 제거). 잘라낸 게 전부면 원문을 그대로 쓴다 — 이름 없는 것보단 낫다.

### 위치(area)

**가장 가까운 역이나 번화가**를 짧게 적게 한다. 도시 이름은 빼라고 시키고(`오사카 우메다` → `우메다`), 그래도 붙여 오면 [`area()`](../src/modules/attraction/providers/openai.provider.ts) 가 떼어낸다. 사용자는 이미 그 도시를 물어봤으므로 도시 이름은 카드에서 아무 정보도 아니다.

### 중복 제거 — `mapUrl` 기준

이름으로 판정하면 `오사카성` / `오사카 성` / `Osaka Castle` 이 전부 다른 값이 된다. `mapUrl` 은 이름을 정규화해 만든 값이라 표기 흔들림을 흡수하고, 무엇보다 **사용자가 도착하는 곳**이 같으면 같은 관광지다.

## 9. 캐시 · DB · 설정

### TTL 이 가장 길다 — 30일

| 도메인 | TTL | 근거 |
|---|---|---|
| 항공권 | 6시간 | 운임이 제일 빨리 변한다 |
| 호텔 | 24시간 | |
| **관광지** | **30일** | 오사카성은 없어지지 않는다 |

캐시 키는 `attraction:{place_id}`.

### DB

호텔·항공권과 같은 테이블을 쓴다.

| 컬럼 | 값 |
|---|---|
| `recommendation_items.hotel_name` | 관광지 이름 |
| `recommendation_items.source_url` | `mapUrl` |
| `recommendation_items.target_url` | `mapUrl` (변환 없음) |
| `recommendation_items.affiliate_link_id` | **`null`** — 정상이다 |
| `recommendation_items.price_from` | **`null`** |

> ⚠️ **입장료를 `price_from` 에 넣지 않는다.** 그 칸은 단위가 원인데 관광지 입장료는 현지 통화(엔·바트·동)라 비교 불가능한 숫자가 섞인다. (0003 마이그레이션 주석 참고)

> ⚠️ **수익 집계에서 관광지를 빼야 한다.** `domain='attraction'` 행은 클릭이 있어도 수수료가 0이다. 안 빼면 전환율이 실제보다 낮게 나온다.

## 11. 알려진 한계

- **맛집을 따로 다루지 않는다** (1절). `맛집` 발화는 일반 관광지 검색으로 가고 `음식/시장` 카테고리가 섞여 나올 뿐이다
- **테마를 파싱하지 않는다** — "아이랑", "야경" 은 뽑지도 고지하지도 않아서 사용자는 반영된 줄 안다
- **사진이 13% 정도 빈다.** 사진 없는 줄이 섞이는 건 정상이다
- **사진 출처를 줄마다 표시하지 못한다** (7절)
- 영업시간·휴무일을 다루지 않는다. 폐관한 곳을 거르는 건 프롬프트 지시뿐이다
