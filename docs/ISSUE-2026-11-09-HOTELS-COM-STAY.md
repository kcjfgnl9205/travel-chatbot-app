# 호텔스닷컴 링크에서 날짜·인원이 빠지는 문제 (2026-11-09)

> **한 줄 요약:** 우리 서버는 날짜·인원을 붙인 상세 주소로 애드픽 링크를 만든다. 그런데 **애드픽 → 호텔스닷컴 제휴(Partnerize) 경유 중에 그 쿼리가 빠져서** 사용자는 날짜 없는 상세 페이지를 받는다. 우리 코드로는 고칠 수 없다. 애드픽 답변을 기다리면서, 카드 안내가 사실과 다르지 않게 먼저 고친다.

## 1. 증상

호텔 카드에서 호텔스닷컴 줄을 누르면 **그 호텔의 상세 페이지는 열리지만 체크인·체크아웃·인원이 비어 있다.** 카드 아래에는 「링크는 12월 2일 체크인 · 12월 5일 체크아웃 · 3명으로 열려요.」가 적혀 있어서, 사용자는 날짜가 들어간 줄 알고 예약하러 간다.

## 2. 우리 쪽 흐름

```
AI 검색 결과(도시 단위로 24시간 저장, 날짜 없음)
  kr.hotels.com/ho1180944672/
        │  카드를 그릴 때 그 사람의 날짜·인원을 붙인다 (withStay)
        ▼
  https://kr.hotels.com/ho1180944672/?chkin=2026-12-02&chkout=2026-12-05&rm1=a3
        │  사용자가 누르면 /r/{clickId} 가 이 주소 그대로 애드픽 링크를 만든다
        │  GET biz.adpick.co.kr/api/{key}/link?url=<위 주소, URL 인코딩>&p_data=…
        ▼
  link.adpick.co.kr/…  →  Partnerize(호텔스닷컴 제휴)  →  kr.hotels.com
```

- AI 결과에 날짜를 넣지 않는 이유: 검색 결과는 같은 도시를 묻는 모든 사람이 하루 동안 같이 쓴다. 날짜를 넣어 저장하면 다음 사람이 남의 날짜로 열린 페이지를 받는다.
- 날짜 칸 이름은 호텔스닷컴 상세 페이지에서 직접 확인한 것이다([search-url.ts](../src/modules/hotel/search-url.ts) `DETAIL_FORMATS`).

## 3. 확인한 것

| # | 시험 | 결과 | 뜻 |
|---|---|---|---|
| 1 | 날짜를 붙인 상세 주소를 **브라우저로 바로** 연다 `https://kr.hotels.com/ho1180944672/?chkin=2026-12-02&chkout=2026-12-05&rm1=a3` | ✅ 날짜·인원이 들어간 채 열린다 | 칸 이름(`chkin`·`chkout`·`rm1`)은 맞다 |
| 2 | 카드의 호텔스닷컴 줄을 누른다 | ❌ `kr.hotels.com/ho1180944672/?clickref=…&affcid=HCOM-KR.DIRECT.PHG…&affdtl=PHG.….ap_…` 로 열리고 날짜가 없다 | 제휴 값만 남고 우리 쿼리는 사라졌다 |
| 3 | 2번 주소 끝의 `affdtl=…ap_…` | 애드픽 추적 값(`ap_…`)이 있다 | **애드픽 변환은 성공했다.** 실패했다면 서버는 원래 주소(날짜 포함)로 보낸다 |
| 4 | 애드픽에서 1번 주소로 링크를 **직접** 만들어 연다 | ❌ 날짜 없이 열린다 | **우리 서버와 무관하게** 애드픽 → 호텔스닷컴 경유에서 빠진다 |
| 5 | 애드픽에 `https://` 없이 `kr.hotels.com/ho…/?chkin=…` 을 넣는다 | `400 올바르지 않는 상품 링크입니다.` | 스킴이 빠진 입력 실수였다. 서버는 항상 `https://` 를 붙여 인코딩해서 보내므로 운영에서는 안 난다 |

### 원인에서 뺀 것

- **AI 가 날짜를 안 줘서** — 아니다. 누가 날짜를 붙이든 애드픽에 들어가는 주소는 같다(4번).
- **애드픽 변환 실패** — 아니다. 최종 주소에 애드픽 추적 값이 있다(3번).
- **호텔스닷컴 칸 이름이 틀려서** — 아니다. 직접 열면 들어간다(1번).

## 4. 사이트별 현황

| 사이트 | 애드픽을 거친 뒤 날짜·인원 | 근거 |
|---|---|---|
| 호텔스닷컴 | ❌ 빠진다 | 3장 4번 |
| 트립닷컴 | ⭕ 유지될 가능성이 높다 (미확정) | 다낭 링크에서 우리가 붙인 `locale=ko-KR&curr=KRW` 가 `AllianceID`·`SID` 와 함께 남아 있었다. 날짜 칸으로 같은 시험은 아직 안 했다 |
| 클룩 | ❓ 확인 안 함 | |
| 마이리얼트립 | — | 호텔에서 뺐다. 제휴 링크가 「서비스 정책에 의해 링크 연결이 차단」으로 막혔다(`c2f8d2d`) |

## 5. 영향

- 호텔스닷컴 줄을 누른 사용자는 **날짜·인원을 다시 입력해야 한다.** 그 한 단계가 이탈 지점이라 날짜를 링크에 넣은 것인데(`a6a425d`), 호텔스닷컴에서는 효과가 없다.
- 더 나쁜 것은 **카드 안내가 사실과 다르다는 점이다.** 「링크는 … 열려요」를 믿고 간 사용자는 기본 날짜로 요금을 보게 된다.

## 6. 대응

### 바로 할 것 (우리 쪽) — 수수료 유지 + 안내를 사실대로

1. 호텔스닷컴을 **「애드픽을 거치면 날짜가 안 넘어가는 사이트」로 표시**한다. 그런 줄이 하나라도 섞인 카드는 「링크는 … 열려요」 대신 「날짜·인원은 반영되지 않았어요」를 적는다.
2. 사이트별 검색 순서를 **트립닷컴 → 호텔스닷컴**으로 바꿔, 같은 호텔이면 날짜가 넘어가는 트립닷컴 줄이 남게 한다.
3. 트립닷컴도 날짜 칸으로 같은 시험(3장 4번)을 해서 4장 표를 확정한다.

### 고르지 않은 대안 — 호텔스닷컴은 날짜를 우선

호텔스닷컴 줄만 애드픽을 거치지 않고 날짜가 붙은 주소로 바로 보낸다. 날짜는 들어가지만 **그 줄의 수수료가 없어진다.** 애드픽 답변이 「불가」로 오면 다시 검토한다.

### 애드픽에 문의할 것

아래를 그대로 보내면 된다.

> 안녕하세요. 호텔스닷컴 상품 링크 관련 문의드립니다.
>
> 상세 페이지 주소에 숙박 조건 쿼리를 붙여 상품 링크를 생성하면, 생성된 링크로 이동했을 때 해당 쿼리가 빠진 채 상세 페이지가 열립니다.
>
> - 상품 URL: `https://kr.hotels.com/ho1180944672/?chkin=2026-12-02&chkout=2026-12-05&rm1=a3`
>   (브라우저로 직접 열면 체크인·체크아웃·인원이 정상 반영됩니다)
> - 생성된 링크로 이동한 최종 주소: `https://kr.hotels.com/ho1180944672/?clickref=…&affcid=HCOM-KR.DIRECT.PHG.…` — `chkin`·`chkout`·`rm1` 이 없습니다
>
> 1. 호텔스닷컴 상품 링크에서 상품 URL 의 쿼리 파라미터를 유지하는 방법이 있을까요?
> 2. 불가능하다면, 다른 형식(경로 등)으로 숙박 날짜·인원을 전달할 방법이 있을까요?
> 3. 트립닷컴·클룩 상품 링크도 쿼리 파라미터가 유지되는지 확인 부탁드립니다.

답변이 「유지 가능」이면 6장 1번의 호텔스닷컴 표시만 되돌리면 된다.
