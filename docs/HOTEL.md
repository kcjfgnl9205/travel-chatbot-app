# 호텔 검색 — 발화에서 말풍선까지

> "오사카 호텔 추천해줘" 한 줄이 들어와서 `listCard` 다섯 줄이 나가기까지.
> 라우터 공통 구조는 [ROUTER.md](./ROUTER.md), 항공권·관광지는 [FLIGHT.md](./FLIGHT.md) · [ATTRACTION.md](./ATTRACTION.md).

세 도메인 중 **가장 먼저 판정된다.** 한 문장에 "항공권이랑 호텔"이 같이 있으면 호텔로 간다 — 우리가 가장 잘 답하는 도메인이기 때문이다.

---

## 1. 어떤 발화가 호텔로 오나

### 키워드

```
호텔 · 숙소 · 묵을 · 잘곳 · 잘 곳 · 숙박 · 리조트 · 호스텔 · 료칸
```

[`intentFromKeywords()`](../src/modules/intent/intent.types.ts) 가 이 정규식을 **가장 먼저** 본다. 걸리면 항공권·관광지 키워드가 같이 있어도 호텔이다.

### 판정은 3단계, 위에서 걸리면 아래는 안 본다

| 단계 | 무엇 | 모델 호출 | 예시 |
|---|---|---|---|
| ① 대표 명령어 | `/호텔 오사카` · `호텔 오사카` (두 단어) | **0회** | 사전에 없는 지명도 그대로 통과 |
| ② 키워드 + 도시 사전 | 호텔 키워드 + 237개 도시표에서 지명 | **0회** | "오사카 호텔 추천해줘" |
| ③ 모델 | 위 둘로 안 되면 gpt-5-mini | 1회 | "도톤보리 근처 묵을 데 있어?" |

②가 성립하려면 셋 다 맞아야 한다 — 키워드로 의도가 분명하고, 사전에서 도시가 **하나만** 잡히고, `에서`·`출발` 이 없어야 한다. "서울에서 오사카 호텔"은 지명이 둘이라 어느 쪽이 목적지인지 사전으로는 못 가리므로 모델로 넘긴다.

해석 결과는 [`intent_cache`](../src/modules/intent/intent.service.ts) 에 **7일** 캐싱된다(키 = 발화 정규화 후 sha256). 같은 문장은 두 번 파싱하지 않는다.

### 발화별 파싱 결과

| 발화 | intent | place | ignored | 경로 |
|---|---|---|---|---|
| `오사카 호텔 추천해줘` | hotel | 오사카 | — | ② |
| `오사카 호텔 4명 9월 22~24일` | hotel | 오사카 | `4명`, `9월 22~24일` | ② |
| `호텔 도톤보리` | hotel | 도톤보리 | — | ① |
| `도톤보리 묵을 데 알려줘` | hotel | 도톤보리 | — | ③ |
| `서울에서 오사카 호텔` | hotel | 오사카 | — | ③ (`에서` 때문에 ②가 빠진다) |
| `일본 호텔 추천해줘` | hotel | 일본 | — | ② → **도시 되묻기** |
| `호텔 예약 어떻게 해?` | unknown | — | — | 도움말 카드 |

`ignored` 는 **검색에 반영하지 않은 조건**이다. 캐시를 지역으로만 가르기 때문에 날짜·인원은 버려지고, 버렸다는 사실이 카드 아래 안내에 적힌다. 고지가 없으면 사용자는 그 날짜에 예약 불가한 호텔을 보고 속았다고 느낀다.

### 여기로 안 오는 발화

1차 필터([`TRAVEL_HINT`](../src/modules/intent/intent.types.ts))에 안 걸리면 **모델을 아예 부르지 않고** 도움말 카드가 나간다. 단톡방에는 봇을 멘션한 잡담이 섞이는데, 인사말까지 모델에 보내면 그게 그대로 요금이고 방 인원수만큼 곱해진다.

## 2. 발화 → 응답 전체 흐름

```
"@여행메이트 오사카 호텔 4명 9월 22~24일 추천해줘"
  │
  │  ── 카카오 5초 예산 안에서 도는 구간 ──────────────────
  │
  ├─ 봇 멘션 제거              utteranceOf()
  ├─ 1차 필터 TRAVEL_HINT      안 걸리면 → 도움말 카드
  ├─ 의도·지명 추출            intent_cache → 명령어 → 키워드 → 모델
  ├─ 지역 정규화               "오사카" → place_id=42   (place_aliases, TTL 없음)
  │                            └ 나라면 → 도시 고르기 카드 (검색 안 함)
  ├─ 캐시 조회                 hotel:42 in search_results
  │    ├ 히트          → listCard 즉시 ✅
  │    ├ 만료 + 항목有 → 예전 것 즉시 + 뒤에서 조용히 갱신
  │    ├ 남이 검색 중  → "먼저 찾고 있어요"
  │    └ 미스          → pending 선점 → 아래로
  │
  │  ── 5초 예산 밖 (백그라운드) ──────────────────────────
  │
  ├─ provider 검색             gpt-5-mini 2단 + 웹 검색 (7~30초)
  ├─ 중복 제거                 sourceUrl 기준
  ├─ 썸네일 확보               예약 페이지에서 og:image 긁기
  ├─ search_results 에 20건 저장 (TTL 24시간)
  └─ 카드 조립 → callbackUrl 로 POST
```

**provider 를 요청 경로에서 부르면 안 된다.** 카카오는 5초 안에 응답을 받아야 하는데 AI 검색은 7~30초다. 요청 경로에서 도는 건 저장소 조회까지다.

## 3. 상황별로 무엇이 나가나

| 상황 | 응답 | 실제 문구 |
|---|---|---|
| 캐시 히트 | `listCard` + 고지 + 퀵리플라이 | 아래 4절 |
| 미스 + 콜백 **켜짐** | `useCallback` → 잠시 뒤 카드 POST | `오사카 호텔을 찾고 있어요. 잠시만요 🔍` |
| 미스 + 콜백 **꺼짐** | `simpleText` | `오사카 호텔을 찾고 있어요 🔍`<br>`30초쯤 뒤에 다시 물어봐 주세요!` |
| 남이 같은 걸 검색 중 | `simpleText` | `오사카 호텔을 먼저 찾고 있어요 🔍`<br>`잠시 뒤 다시 물어봐 주세요!` |
| 결과 0건 | `simpleText` | `오사카 호텔 정보를 지금은 정리하지 못했어요 🙏` |
| 검색 실패(모델 오류·타임아웃) | `simpleText` | `오사카 호텔을 불러오지 못했어요 🙏` |
| **키가 없어 검색 불가** | `simpleText` | `지금은 오사카 호텔 검색이 안 되고 있어요 🙏`<br>`고쳐두는 대로 다시 알려드릴게요.` |
| 나라를 말함 (`일본 호텔`) | 도시 고르기 `listCard` + 안내 | `일본 어느 도시의 호텔을 찾을까요?` |
| 지명이 없음 (`호텔 추천해줘`) | `simpleText` 되묻기 | `어느 지역 호텔을 찾으세요?`<br>`예) 오사카 호텔 추천해줘` |
| 여행 무관 / 의도 불명 | 도움말 `listCard` | 할 수 있는 세 가지 |

> ⚠️ **"잘못된 검색입니다" 같은 오류 문구를 쓰지 않는다.** 인사말·잡담까지 오류로 취급하면 단톡방이 딱딱해진다. 할 수 있는 것을 예시와 함께 보여주는 것이 안내다.

> ⚠️ **검색 불가(키 없음)와 결과 0건은 다른 문구다.** "30초 뒤에 다시" 는 결과가 영원히 안 오는데 기다리게 하는 거짓말이다. 그때는 선점도, 대기 응답도 만들지 않는다.

> ⚠️ **콜백은 오픈빌더에서 그 블록의 [콜백 사용] 을 켠 경우에만** 실린다. 꺼져 있으면 사용자는 같은 질문을 두 번 해야 한다 — 서버가 아니라 설정 문제다.

## 4. 카드 한 장 해부

### 나가는 말풍선 (최대 3개)

```
① listCard      결과 5줄 + [더 보기] 버튼
② simpleText    고지 — 반영하지 않은 조건이 있을 때만
   quickReplies  다음 질문 ("도쿄 호텔", "후쿠오카 호텔")
```

안내를 카드 안에 넣을 자리가 없다. `header` 도 40자, 줄 설명도 40자다. 그래서 말풍선을 하나 더 세운다. **순서가 중요하다 — 카드가 먼저다.** 안내가 위에 오면 결과를 가린다.

### 실제 JSON

```json
{
  "version": "2.0",
  "template": {
    "outputs": [
      { "listCard": {
          "header": { "title": "오사카 호텔 5곳" },
          "items": [
            { "title": "호텔 그란비아 오사카",
              "description": "1박 182,000원~ · 평점 9.0 · 우메다",
              "imageUrl": "https://ak-d.tripcdn.com/images/....jpg",
              "link": { "web": "https://bot.nolmoa.com/r/Ab3xY9kQmN2p" } }
          ],
          "buttons": [
            { "label": "더 보기", "action": "block", "blockId": "...",
              "messageText": "오사카 호텔 더 보기",
              "extra": { "cache_key": "hotel:42", "offset": 5 } }
          ] } },
      { "simpleText": { "text": "날짜·인원(4명, 9월 22~24일)은 반영되지 않았어요." } }
    ],
    "quickReplies": [
      { "label": "도쿄 호텔", "action": "message", "messageText": "도쿄 호텔 추천해줘" },
      { "label": "후쿠오카 호텔", "action": "message", "messageText": "후쿠오카 호텔 추천해줘" }
    ]
  }
}
```

### 머리글

| 페이지 | 문구 |
|---|---|
| 1페이지 | `오사카 호텔 5곳` |
| 2페이지부터 | `오사카 호텔 6~10번째` |

2페이지부터 몇 번째인지 알려준다. 안 그러면 같은 카드가 또 온 것처럼 보인다.

### 한 줄의 제목·설명

```
title        호텔명 그대로                          (40자, 2줄)
description  가격 · 평점 · 태그[0]                  (40자, 1줄)
imageUrl     썸네일 (없으면 그 줄만 사진 없이)
link.web     /r/{clickId}  ← 애드픽이 아니라 우리 리다이렉트
```

설명은 [`listDescription()`](../src/modules/hotel/hotel.types.ts) 이 **있는 것만** 이어 붙인다:

| 필드 | 있을 때 | 없을 때 |
|---|---|---|
| 가격 | `1박 182,000원~` | `가격 문의` (항상 나옴) |
| 평점 | `평점 9.0` | 생략 |
| 태그 | `우메다` (첫 번째만) | 생략 |

> 평점은 `9` 가 아니라 `9.0` 으로 찍는다. 소수점 한 자리를 유지해야 "평점 9.0 / 평점 8.9" 처럼 폭이 고르게 보인다.

### 고지 말풍선

[`noticeText()`](../src/modules/kakao/cards.ts) 가 만든다. **남길 게 없으면 빈 문자열이고, 그러면 말풍선 자체가 안 나간다.**

```
날짜·인원(4명, 9월 22~24일)은 반영되지 않았어요.
```

무엇을 버렸는지 **이름을 붙여준다** — `날짜` · `인원` · `예산`, 못 가리면 `일부 조건`.

> "AI 가 정리한 참고 정보" 같은 상시 문구는 뺐다. 매번 나가는 줄은 곧 아무도 안 읽는 줄이 된다. **정말로 알아야 할 때만** 말풍선이 뜬다.
> "예전에 찾아둔 정보예요" 도 뺐다. 사용자가 할 수 있는 일이 없는 사정이다.

### 더 보기

한 번의 AI 검색으로 **20건**을 찾아 한 행에 통째로 저장하고, `listCard` 가 5줄이므로 **5건씩 4페이지**로 낸다. 2페이지를 위해 AI 를 다시 부르지 않는다 — 더보기는 **AI 호출 0회**가 전제다.

서버는 "누가 어디까지 봤는지"를 기억하지 않는다. **버튼이 커서를 들고 다닌다** (`extra.cache_key` + `offset`). 다음 페이지가 없으면 버튼을 달지 않는다.

## 5. 결과는 어떻게 만들어지나

[`OpenAiHotelProvider`](../src/modules/hotel/providers/openai.provider.ts) — gpt-5-mini + 웹 검색 **2단 호출**. 뼈대는 세 도메인이 [`TwoStageSearch`](../src/modules/openai/two-stage.ts) 로 공유한다.

```
1차  web_search 로 후보 30곳 수집          (구조화 JSON)
2차  가격·위치·평점·특징을 비교해 20곳 선정 (구조화 JSON)
3차  썸네일 확보                            (모델 아님 — 페이지 긁기)
```

**왜 두 번 부르나** — 한 번에 시키면 모델이 검색 결과를 요약하는 데 힘을 쓰고 비교·선별은 대충 한다.

> ⚠️ **두 호출 다 구조화 출력을 건다.** 1차를 자유 텍스트로 뒀더니 모델이 "웹 검색을 진행해도 될까요? 날짜를 알려주세요" 라고 되묻고 끝나서 후보가 0개가 됐다. 상대는 사람이 아니라 프로그램이라 그 질문에 답할 사람이 없다.

> ⚠️ **1차는 `tool_choice: required` 다.** `auto` 로 두면 모델이 검색을 건너뛰고 기억으로 답한다. 실측으로 같은 질의에 어떤 때는 웹을 20번 뒤지고, 어떤 때는 5초 만에 빈 배열을 뱉었다.

> ⚠️ **후보가 0개면 2차를 부르지 않는다.** 빈손에서 고르라고 하면 모델이 없는 호텔을 지어낸다.

### 예약 링크 — 네 곳만 인정한다

```
trip.com · myrealtrip.com · klook.com · hotels.com
```

모델은 없는 URL 을 그럴듯하게 만들어낸다. 그게 애드픽 변환을 타고 나가면 404 로 떨어진다. 호스트라도 걸러서 피해를 줄인다 — 목록 밖 링크(아고다·부킹닷컴)는 **버린다**.

**한국어 페이지를 강제한다.** 프롬프트로 시키고(`kr.trip.com`, `klook.com/ko/`, `kr.hotels.com`), 그게 안 먹었을 때를 위해 [`toKoreanUrl()`](../src/common/booking-url.ts) 이 마지막 방어선으로 호스트·쿼리를 고친다. 영문 페이지가 뜨면 사용자는 예약까지 못 간다.

### 썸네일 — 모델에게 안 받는다

```
① 모델이 준 주소      거의 없다 (1차 스키마에 이미지 필드가 없고 web_search 는 텍스트만 준다)
② 예약 페이지 긁기    og:image → ld+json → 본문 <img>    ← 실질적인 경로
③ 살아 있는지 확인    HEAD → 막히면 Range GET 1KB
```

> ⚠️ **og:image 라고 다 쓰면 안 된다.** 사이트들은 상세 페이지에도 공용 로고를 og:image 로 박아둔다 (마이리얼트립의 `mrt_main_og_image.png` 를 실제로 받았다). 그대로 쓰면 호텔 다섯 줄이 전부 같은 로고가 된다 — **이미지가 없는 것보다 나쁘다.** 걸리면 아래층으로 내려간다.

CDN 마다 사정이 다르다. trip.com CDN 은 **HEAD 에 content-type 을 안 준다** — 없다고 버리면 이미지를 다 놓친다. 그래서 타입을 안 알려주면 200 을 믿는다.

페이지를 읽을 땐 **브라우저 UA 를 보낸다.** 안 보내면 hotels.com 이 403·429 를 준다. 본문은 앞부분 몇백 KB 만 읽는다 — 예약 페이지는 200~400KB 인데 이미지 주소는 앞쪽에 있고, 5곳을 동시에 읽기 때문이다.

**사진을 못 구했다고 호텔을 빼지는 않는다.** 그 줄만 사진 없이 나간다.

### 중복 제거 — `sourceUrl` 기준

AI 는 같은 호텔을 이름만 다르게 여러 번 준다('호텔 그란비아 오사카' / 'Hotel Granvia Osaka'). 이름은 못 믿으므로 예약 주소로 판정한다. **저장 전에** 지운다 — 저장 후에 지우면 20건이 페이지마다 줄고, 2페이지에 1페이지에서 본 호텔이 다시 나온다.

## 6. 캐시와 비용

| 무엇 | 어디 | TTL |
|---|---|---|
| 검색 결과 20건 | `search_results` + 프로세스 메모리 | **24시간** |
| 실패·빈손 | 같음 (`status='failed'`) | 10분 |
| 발화 해석 | `intent_cache` + 메모리 | 7일 |
| 지역 별칭 | `place_aliases` + 메모리 | 없음 |
| 애드픽 링크 | `affiliate_links` | 30일 |

캐시 키는 **`hotel:{place_id}`** — 도시 문자열이 아니라 지역 ID 다. 표기가 갈리면(`오사카`/`osaka`/`오사카시`) 같은 도시를 물어도 AI 가 새로 돌기 때문에, [`place_aliases`](../src/modules/places/places.service.ts) 가 이걸 한 ID 로 모은다.

**날짜·인원은 키에 없다.** 넣으면 캐시가 거의 안 맞아 매 질문이 AI 호출이 된다. 대신 반영하지 않았다는 사실을 카드 아래에 반드시 적는다.

### 동시 호출 방지 (single-flight)

캐시가 빈 상태에서 세 명이 동시에 "오사카 호텔"을 치면 **먼저 꽂은 하나만** 검색한다. 프로세스 안에서는 Map 에 동기적으로, 프로세스 밖으로는 `insert ... on conflict do nothing` 으로 가른다. 나머지는 "먼저 찾고 있어요" 를 받는다.

### 빈손은 한 번으로 굳히지 않는다

모델은 같은 질의에도 가끔 빈손으로 돌아온다. 한 번에 10분을 굳히면 그게 그대로 10분짜리 장애가 된다 — "도쿄 호텔"이 실제로 그랬다. **연속 두 번**이어야 진짜 없는 것으로 보고, 첫 번째는 1분만 굳힌다.

### 애드픽 rate limit

분당 **60회**(`linkonly=true`)다. 호텔 5건이면 캐시 미스 시 요청 하나에 5회를 쓴다. 그래서 **페이지를 자른 뒤에** 변환한다 — 이번 카드에 안 나갈 호텔까지 변환하면 한도를 헛되이 쓴다.

## 7. DB 에 남는 것

```
recommendations        추천 1회 (도메인·지역·provider·소요시간·캐시히트 여부)
recommendation_items   노출된 줄 (호텔명·가격·clickId·원본주소·최종목적지)
affiliate_links        sourceUrl → 커미션 링크 (30일 캐시)
messages               발화 원문
```

**호텔 마스터 테이블이 없다.** 이름으로는 "같은 호텔"을 못 묶기 때문이다. 호텔의 신원은 `source_url` 이고, `affiliate_links` 가 `(partner, source_url)` 유니크로 그 역할을 겸한다.

클릭은 행이 아니라 **카운터**다. 같은 줄을 10번 눌러도 `recommendation_items.click_count` 가 10이 된다. 노출과 클릭이 한 행에 있어 CTR 이 join 없이 나오고, 리다이렉트 DB 왕복이 1회로 끝난다.

**변환 실패는 경고로 남는다.** 목적지가 원본과 같으면 커미션 링크가 아니라는 뜻이고, 세지 않으면 "링크는 열리는데 수수료가 안 들어온다"를 영영 못 찾는다.

## 9. 확인하는 방법

```bash
# ① 해석만 — 싸고 빠르다. "왜 도움말이 나오지?" 를 가릴 때 여기부터
curl -s localhost:8000/api/v1/debug/parse \
  -H 'content-type: application/json' -H "X-Debug-Token: $DEBUG_TOKEN" \
  -d '{"utterance":"오사카 호텔 4명 9월 22~24일 추천해줘"}' | jq

# ② 전체 파이프라인 (동기, 7~30초, OpenAI 요금)
#    캐시를 읽지도 쓰지도 않고, 통계도 남기지 않는다.
curl -s localhost:8000/api/v1/debug/search \
  -H 'content-type: application/json' -H "X-Debug-Token: $DEBUG_TOKEN" \
  -d '{"utterance":"오사카 호텔 추천해줘"}' | jq '.response'
```

②는 **사용자에게 실제로 배달될 말풍선을 그대로** 돌려준다. 카드 조립은 운영과 같은 코드를 태운다.

라우터는 5초 예산 때문에 검색을 백그라운드로 던지므로, 스킬 응답만 봐서는 검색 성공 여부를 알 수 없다 — 늘 "찾고 있어요"다. 그래서 이 엔드포인트가 있다.

```bash
# 로그에서 이 검색만 보기
docker compose logs -f app | grep 'hotel search city=오사카'
```

```
hotel search city=오사카 searches=3 candidates=28 chars=4210 ms=12400
hotel rank city=오사카 picks=20 ms=6100
```

`searches=0` 이면 모델이 웹을 안 뒤지고 기억으로 답한 것이다 — URL 과 가격이 특히 위험하다.
