# 호텔 검색 — 발화에서 말풍선까지

> "오사카 호텔 추천해줘" 한 줄이 들어와서 `listCard` 다섯 줄이 나가기까지.
> 라우터 공통 구조는 [ROUTER.md](./ROUTER.md), 항공권·관광지는 [FLIGHT.md](./FLIGHT.md) · [ATTRACTION.md](./ATTRACTION.md).

세 도메인 중 **가장 먼저 판정된다.** 한 문장에 "항공권이랑 호텔"이 같이 있으면 호텔로 간다 — 우리가 가장 잘 답하는 도메인이기 때문이다.

---

## 1. 어떤 발화가 호텔로 오나

### 키워드

```
호텔 · 숙소 · 묵을 · 잘곳 · 잘 곳 · 숙박 · 리조트 · 호스텔 · 료칸
```

[`intentFromKeywords()`](../src/modules/intent/intent.types.ts) 가 이 정규식을 **가장 먼저** 본다. 걸리면 항공권·관광지 키워드가 같이 있어도 호텔이다.

### 판정은 3단계, 위에서 걸리면 아래는 안 본다

| 단계 | 무엇 | 모델 호출 | 예시 |
|---|---|---|---|
| ① 대표 명령어 | `/호텔 오사카` · `호텔 오사카` (두 단어) | **0회** | 사전에 없는 지명도 그대로 통과 |
| ② 키워드 + 도시 사전 | 호텔 키워드 + 237개 도시표에서 지명 | **0회** | "오사카 호텔 추천해줘" |
| ③ 모델 | 위 둘로 안 되면 모델(`OPENAI_PARSE_MODEL`) | 1회 | "도톤보리 근처 묵을 데 있어?" |

②가 성립하려면 셋 다 맞아야 한다 — 키워드로 의도가 분명하고, 사전에서 도시가 **하나만** 잡히고, `에서`·`출발` 이 없어야 한다. "서울에서 오사카 호텔"은 지명이 둘이라 어느 쪽이 목적지인지 사전으로는 못 가리므로 모델로 넘긴다.

해석 결과는 [`intent_cache`](../src/modules/intent/intent.service.ts) 에 **7일** 캐싱된다(키 = 발화 정규화 후 sha256). 같은 문장은 두 번 파싱하지 않는다.

### 발화별 파싱 결과

| 발화 | intent | place | ignored | 경로 |
|---|---|---|---|---|
| `오사카 호텔 추천해줘` | hotel | 오사카 | — | ② |
| `오사카 호텔 4명 9월 22~24일` | hotel | 오사카 | `4명`, `9월 22~24일` | ② |
| `호텔 도톤보리` | hotel | 도톤보리 | — | ① |
| `도톤보리 묵을 데 알려줘` | hotel | 도톤보리 | — | ③ |
| `서울에서 오사카 호텔` | hotel | 오사카 | — | ③ (`에서` 때문에 ②가 빠진다) |
| `일본 호텔 추천해줘` | hotel | 일본 | — | ② → **도시 되묻기** |
| `호텔 예약 어떻게 해?` | unknown | — | — | 도움말 카드 |

`ignored` 는 **검색에 반영하지 않은 조건**이다. 캐시를 지역으로만 가르기 때문에 날짜·인원은 버려지고, 버렸다는 사실이 카드 아래 안내에 적힌다. 고지가 없으면 사용자는 그 날짜에 예약 불가한 호텔을 보고 속았다고 느낀다.

### 날짜·인원은 목록이 아니라 링크로 간다

**목록은 여전히 지역으로만 찾는다**(캐시를 지역으로 가른다). 날짜·인원이 들어가는 자리는 **링크**다 — 상세 페이지를 맨 주소로 열면 사용자가 날짜를 다시 입력해야 하고, 그 한 단계가 이탈 지점이다. 항공권이 같은 이유로 검색된 상태를 연다.

| 말하지 않았을 때 | 값 | 어디서 |
|---|---|---|
| 체크인 | **내일** | `CHECKIN_AFTER_DAYS` |
| 체크아웃 | 체크인 + **1박** | `DEFAULT_NIGHTS` |
| 인원 | **2명** | `DEFAULT_ADULTS` |

기본값은 [`resolveStay`](../src/modules/hotel/search-url.ts) **한 곳에만** 있다. 주소를 만드는 쪽과 고지를 적는 쪽이 각자 채우면 적어놓은 날짜와 열리는 날짜가 갈린다.

- **인원은 6명까지다**(`MAX_ADULTS`). 그 위는 제휴몰이 객실을 나누라고 요구하는데 방을 몇 개로 쪼갤지 우리가 알 수 없다. 6명으로 맞추고 **맞췄다고 카드에 적는다** — 말없이 줄이면 8명이라고 말한 사람이 8명으로 검색된 줄 안다.
- **되물어야 하는 날짜가 셋이다**([`stayProblem`](../src/modules/hotel/search-url.ts)) — ①연도까지 적은 지난 날짜 ②체크아웃이 체크인보다 빠름 ③**체크인과 체크아웃이 같은 날**. ③은 호텔에만 있다(0박은 검색이 안 된다). 항공권에서 같은 날은 당일치기라 멀쩡한 일정이다. 셋 다 **둘 다 콕 집어 말했을 때만** 문제로 삼는다 — 파서가 상대 표현을 잘못 읽은 것까지 되물으면 말한 적 없는 날짜를 질문받는다.
- 되묻기 카드는 후보를 `message` 버튼으로 내놓는다. **카카오에는 날짜 선택 버튼이 없다.**

### 상세 페이지에 박는 칸 ([`DETAIL_FORMATS`](../src/modules/hotel/search-url.ts))

**전부 실제 상세 페이지를 날짜·인원 넣고 연 뒤 주소창을 복사한 것이다**(2026-11-09). 검색 결과 주소와 같은 규칙이다 — **지어낸 파라미터는 넣지 않는다.**

| 제휴몰 | 확인한 경로 | 날짜 | 인원 |
|---|---|---|---|
| 호텔스닷컴 | `/ho{번호}/...` | `chkin` · `chkout` | **`rm1=a{N}`** (객실별로 적는다) |
| 트립닷컴 | `/hotels/detail/` | `checkIn` · `checkOut` | `adult` · `children=0` · `crn=1` |
| 클룩 | `/{로케일}/hotels/detail/...` | `check_in` · `check_out` | `adult_num` · `child_num=0` · `room_num=1` |
| 마이리얼트립 (호텔에서 뺐다) | `/union/products/{번호}` | `checkIn` · `checkOut` | `adultCount` · `childCount=0` |

- 우리가 만들 수 없는 값은 덜어냈다 — 추적 토큰(`pwa_ts`·`searchId`·`source_price_token`·`serverData`·`hoteluniquekey`), 내부 번호(`regionId`·`neighborhoodId`·`expediaPropertyId`), 호텔 주소가 이미 들고 있는 것(`hotelId`·`cityId`).
- **호스트만 보고 붙이지 않는다.** 같은 사이트에도 상세 주소가 여러 꼴이고(`/hotels/detail/` vs `/hotels/{도시}-hotel-detail-{번호}/`), 확인하지 않은 꼴에서 파라미터가 무시되면 **카드에 적은 날짜와 열리는 날짜가 갈린다.**
- 아직 확인 안 된 꼴: 트립닷컴 `/hotels/{도시}-hotel-detail-{번호}/`, 클룩 `/{로케일}/hotel/{번호}-{이름}/`, 마이리얼트립 `www.myrealtrip.com/offers/{번호}`.

### 붙는 것과 닿는 것은 다르다 ([`stayReachesUser`](../src/modules/hotel/search-url.ts))

**호텔스닷컴은 주소에 붙어도 사용자에게 닿지 않는다.** 애드픽 → Partnerize 경유에서 쿼리가 통째로 날아간다 — 브라우저로 직접 열면 반영되고, 애드픽에서 직접 만든 링크도 같이 빠지므로 **우리 코드로는 못 고친다**([ISSUE 문서](./ISSUE-2026-11-09-HOTELS-COM-STAY.md), 2026-11-09).

| | 조건이 주소에 붙나 | 사용자에게 닿나 | 카드가 날짜를 말하나 |
|---|---|---|---|
| 트립닷컴 `/hotels/detail/` | ⭕ | ⭕ **실측 확인**(2026-11-10) | ⭕ |
| 트립닷컴 `/{도시}-hotel-detail-{번호}/` | ❌ 확인 안 된 꼴 | ❌ | ❌ |
| **호텔스닷컴 상세** (지금은 안 쓴다) | ⭕ | **❌ 애드픽 경유에서 빠진다** | **❌** |
| 확인 안 된 주소 꼴 | ❌ | ❌ | ❌ |

> ⚠️ **트립닷컴 상세 주소에도 꼴이 둘이다.** 날짜를 박을 수 있는 건 `?hotelId=` 꼴뿐이라, 모델이 경로 꼴로 주면 그 줄은 조건 없이 나가고 **카드 전체가 날짜를 말하지 못한다.** 프롬프트에서 `?hotelId=` 꼴을 먼저 적게 해뒀지만, 경로 꼴도 날짜가 먹는지 확인되면 `DETAIL_FORMATS` 에 한 줄 추가해 이 구멍을 막을 수 있다.

- **한 줄이라도 안 닿으면 그 카드는 조건을 말하지 않는다**([`stayApplied`](../src/modules/search/search.service.ts)) — 「링크는 … 열려요」 대신 「날짜·인원은 반영되지 않았어요」가 나간다. 그 안내를 믿고 간 사용자가 기본 날짜로 요금을 보는 것이 가장 나쁜 실패다.
- **그래도 주소에는 계속 붙인다.** 애드픽 변환이 실패하면 리다이렉트가 원본 주소로 보내는데, 그때는 조건이 살아서 간다.
- 같은 호텔이 두 곳에서 오면 **트립닷컴 줄이 남는다**([`SITE_BRANCHES`](../src/modules/hotel/providers/openai.provider.ts) 순서) — 날짜가 넘어가는 쪽을 남긴다.
- 줄마다 어느 쪽인지는 `POST /api/v1/debug/search` 의 `links[]` 에서 본다 (`withStay` · `staySupported` · `stayReachesUser`).

### 여기로 안 오는 발화

1차 필터([`TRAVEL_HINT`](../src/modules/intent/intent.types.ts))에 안 걸리면 **모델을 아예 부르지 않고** 도움말 카드가 나간다. 단톡방에는 봇을 멘션한 잡담이 섞이는데, 인사말까지 모델에 보내면 그게 그대로 요금이고 방 인원수만큼 곱해진다.

## 2. 발화 → 응답 전체 흐름

```
"@가자고 오사카 호텔 4명 9월 22~24일 추천해줘"
  │
  │  ── 카카오 5초 예산 안에서 도는 구간 ──────────────────
  │
  ├─ 봇 멘션 제거              utteranceOf()
  ├─ 1차 필터 TRAVEL_HINT      안 걸리면 → 도움말 카드
  ├─ 의도·지명 추출            intent_cache → 명령어 → 키워드 → 모델
  ├─ 지역 정규화               "오사카" → place_id=42   (place_aliases, TTL 없음)
  │                            └ 나라면 → 도시 고르기 카드 (검색 안 함)
  ├─ 캐시 조회                 hotel:42 in search_results
  │    ├ 히트          → listCard 즉시 ✅
  │    ├ 만료 + 항목有 → 예전 것 즉시 + 뒤에서 조용히 갱신
  │    ├ 남이 검색 중  → "먼저 찾고 있어요"
  │    └ 미스          → pending 선점 → 아래로
  │
  │  ── 5초 예산 밖 (백그라운드) ──────────────────────────
  │
  ├─ provider 검색             gpt-5.6-luna 2단 + 웹 검색 (7~30초)
  ├─ 중복 제거                 sourceUrl 기준
  ├─ 썸네일 확보               예약 페이지에서 og:image 긁기
  ├─ search_results 에 20건 저장 (TTL 24시간)
  └─ 카드 조립 → callbackUrl 로 POST
```

**provider 를 요청 경로에서 부르면 안 된다.** 카카오는 5초 안에 응답을 받아야 하는데 AI 검색은 7~30초다. 요청 경로에서 도는 건 저장소 조회까지다.

## 3. 상황별로 무엇이 나가나

| 상황 | 응답 | 실제 문구 |
|---|---|---|
| 캐시 히트 | `listCard` + 고지 + 퀵리플라이 | 아래 4절 |
| 미스 + 콜백 **켜짐** | `useCallback` → 잠시 뒤 카드 POST | `오사카 호텔을 찾고 있어요. 잠시만요 🔍` |
| 미스 + 콜백 **꺼짐** | `simpleText` | `오사카 호텔을 찾고 있어요 🔍`<br>`30초쯤 뒤에 다시 물어봐 주세요!` |
| 남이 같은 걸 검색 중 | `simpleText` | `오사카 호텔을 먼저 찾고 있어요 🔍`<br>`잠시 뒤 다시 물어봐 주세요!` |
| 결과 0건 | `simpleText` | `오사카 호텔 정보를 지금은 정리하지 못했어요 🙏` |
| 검색 실패(모델 오류·타임아웃) | `simpleText` | `오사카 호텔을 불러오지 못했어요 🙏` |
| **키가 없어 검색 불가** | `simpleText` | `지금은 오사카 호텔 검색이 안 되고 있어요 🙏`<br>`고쳐두는 대로 다시 알려드릴게요.` |
| 나라를 말함 (`일본 호텔`) | 도시 고르기 `listCard` + 안내 | `일본 어느 도시의 호텔을 찾을까요?` |
| 지명이 없음 (`호텔 추천해줘`) | `simpleText` 되묻기 | `어느 지역 호텔을 찾으세요?`<br>`예) 오사카 호텔 추천해줘` |
| 여행 무관 / 의도 불명 | 도움말 `listCard` | 할 수 있는 세 가지 |

> ⚠️ **"잘못된 검색입니다" 같은 오류 문구를 쓰지 않는다.** 인사말·잡담까지 오류로 취급하면 단톡방이 딱딱해진다. 할 수 있는 것을 예시와 함께 보여주는 것이 안내다.

> ⚠️ **검색 불가(키 없음)와 결과 0건은 다른 문구다.** "30초 뒤에 다시" 는 결과가 영원히 안 오는데 기다리게 하는 거짓말이다. 그때는 선점도, 대기 응답도 만들지 않는다.

> ⚠️ **콜백은 오픈빌더에서 그 블록의 [콜백 사용] 을 켠 경우에만** 실린다. 꺼져 있으면 사용자는 같은 질문을 두 번 해야 한다 — 서버가 아니라 설정 문제다.

## 4. 카드 한 장 해부

### 나가는 말풍선 (최대 3개)

```
① listCard      결과 5줄 + [더 보기] 버튼
② simpleText    고지 — 반영하지 않은 조건이 있을 때만
③ textCard      "가자고에게 이어서 말하기" + [@가자고] 멘션 버튼
```

안내를 카드 안에 넣을 자리가 없다. `header` 도 40자, 줄 설명도 40자다. 그래서 말풍선을 하나 더 세운다. **순서가 중요하다 — 카드가 먼저다.** 안내가 위에 오면 결과를 가린다.

> ⚠️ **셋이면 꽉 찬다(최대 3개).** 하나를 더 얹으면 `MAX_OUTPUTS` 에서 잘려 멘션 버튼이 조용히 사라진다.

> ⚠️ **퀵리플라이를 쓰지 않는다.** 팀채팅 챗봇은 `QuickReplies` 를 지원하지 않는다(그룹 챗봇 beta 가이드 표 3). 한동안 모든 응답에 달아뒀는데 단톡방에서는 아무것도 안 보였고, 누를 게 없으니 되묻기에서 대화가 그대로 끊겼다. 지금 그 자리에 있는 것이 ③이다.

```json
          ],
          "buttons": [

              "messageText": "오사카 호텔 더 보기",
              "extra": { "cache_key": "hotel:42", "offset": 5 } }
          ] } },
      { "simpleText": { "text": "날짜·인원(4명, 9월 22~24일)은 반영되지 않았어요." } },
      { "textCard": {
          "description": "가자고에게 이어서 말하기",
          "buttons": [ { "label": "@가자고", "action": "mention" } ] } }
    ]
  }
}
```

`mention` 은 그룹 챗봇 전용 **봇 응답 버튼 플러그인**이다. 누르면 입력창에 `@봇이름` 이 들어간다 — 단톡방에서는 봇을 멘션한 메시지만 서버로 오므로, 이 버튼이 없으면 사용자가 멘션을 빼먹고 "봇이 죽었다" 고 느낀다.

**문장까지 넣어주지는 않는다.** 들어가는 건 멘션뿐이라, 이 버튼을 다는 자리에는 "뭐라고 치면 되는지" 예문이 같이 있어야 한다.

> ⚠️ 액션 이름은 **`mention`** 이다. 예전에 짐작으로 쓴 `talk_mention` 은 없는 값이라 **응답 전체가 렌더링되지 않았다** — 카드까지 같이 사라진다.

### 머리글

| 페이지 | 문구 |
|---|---|
| 1페이지 | `오사카 호텔 5곳` |
| 2페이지부터 | `오사카 호텔 6~10번째` |

2페이지부터 몇 번째인지 알려준다. 안 그러면 같은 카드가 또 온 것처럼 보인다.

### 한 줄의 제목·설명

```
title        호텔명 그대로                          (40자, 2줄)
description  평점(리뷰 수) · 태그[0] · 출처 사이트   (40자, 1줄)
imageUrl     썸네일 (없으면 그 줄만 사진 없이)
link.web     /r/{clickId}  ← 애드픽이 아니라 우리 리다이렉트
```

설명은 [`listDescription()`](../src/modules/hotel/hotel.types.ts) 이 **있는 것만** 이어 붙인다:

| 필드 | 있을 때 | 없을 때 |
|---|---|---|
| 평점 | `평점 9.0`, 리뷰 수까지 있으면 `평점 9.0(1,234)` | 생략 (리뷰 수만으로는 안 적는다) |
| 지역 | `우메다` (`tags` 첫 번째) | 생략 |
| 출처 | `트립닷컴` · `호텔스닷컴` · `클룩` | 생략 |

셋 다 없으면 **빈 줄**이고, 그 줄만 설명 없이 나간다. 출처는 맨 뒤다 — 설명이 넘치면 끝부터 잘리므로 평점·지역이 먼저 산다. (지금은 트립닷컴 한 곳만 쓰므로 출처도 한 가지다. 사이트를 다시 늘리면 줄마다 달라진다.)

> ⚠️ **가격은 적지 않는다.** 1차 검색은 날짜 없이 일반 요금대를 훑는데 링크는 그 사람이 말한 날짜로 열린다([`withStay`](../src/modules/hotel/search-url.ts)). 그래서 적어놓은 「1박 182,000원~」과 열어서 보는 요금이 어긋날 수밖에 없었다 — **숫자가 틀리는 것은 안 보여주는 것보다 나쁘다.**
>
> `priceFrom` 은 계속 받아서 `recommendation_items.price` 에 저장한다. 화면에서 뺀 것이지 버린 게 아니다 — 집계가 그 값을 보고, 2차 호출이 가격대를 섞어 고르는 데도 쓴다.

> 평점은 `9` 가 아니라 `9.0` 으로 찍는다. 소수점 한 자리를 유지해야 "평점 9.0 / 평점 8.9" 처럼 폭이 고르게 보인다.

### 고지 말풍선

[`noticeText()`](../src/modules/kakao/cards.ts) 가 만든다. **남길 게 없으면 빈 문자열이고, 그러면 말풍선 자체가 안 나간다.**

```
날짜·인원(4명, 9월 22~24일)은 반영되지 않았어요.
```

무엇을 버렸는지 **이름을 붙여준다** — `날짜` · `인원` · `예산`, 못 가리면 `일부 조건`.

> "AI 가 정리한 참고 정보" 같은 상시 문구는 뺐다. 매번 나가는 줄은 곧 아무도 안 읽는 줄이 된다. **정말로 알아야 할 때만** 말풍선이 뜬다.
> "예전에 찾아둔 정보예요" 도 뺐다. 사용자가 할 수 있는 일이 없는 사정이다.

### 더 보기

한 번의 AI 검색으로 **20건**을 찾아 한 행에 통째로 저장하고, `listCard` 가 5줄이므로 **5건씩 4페이지**로 낸다. 2페이지를 위해 AI 를 다시 부르지 않는다 — 더보기는 **AI 호출 0회**가 전제다.

서버는 "누가 어디까지 봤는지"를 기억하지 않는다. **버튼이 커서를 들고 다닌다** (`extra.cache_key` + `offset`). 다음 페이지가 없으면 버튼을 달지 않는다.

## 5. 결과는 어떻게 만들어지나

[`OpenAiHotelProvider`](../src/modules/hotel/providers/openai.provider.ts) — gpt-5.6-luna + 웹 검색 **2단 호출**. 뼈대는 세 도메인이 [`TwoStageSearch`](../src/modules/openai/two-stage.ts) 로 공유한다.

```
1차  사이트별 web_search 갈래                (구조화 JSON + 검색 출처)
       트립닷컴 한 갈래, site: 검색으로 상세 페이지만
     → 출처 대조 · 상세 주소 꼴 · 사이트 간 중복 제거
2차  가격·위치·평점·특징을 비교해 20곳 선정 (번호만)
3차  페이지 확인                            (모델 아님 — 페이지 읽기)
       404·410 버림 · 제목에 호텔 이름이 없으면 버림 · 썸네일 긁기
```

### 실제 검색 결과만 쓴다

모델이 JSON 에 적은 주소는 **모델이 타이핑한 값**이다. 검색 결과에서 옮겨 적을 수도, 기억으로 지어낼 수도, 도시 목록 페이지를 호텔마다 붙일 수도 있다(시즈오카는 31곳이 전부 목록 주소였다, 2026-11-09). 그래서 모델의 말이 아니라 **바깥의 증거**로 가린다([`verify.ts`](../src/modules/hotel/verify.ts)).

| 검사 | 무엇과 대조하나 | 떨어지면 |
|---|---|---|
| 검색을 했나 | 응답의 `web_search_call` 수 | 그 갈래를 통째로 버린다 — 기억으로 쓴 답이다 |
| 출처에 있나 | `include: web_search_call.action.sources` 로 받은 **검색 도구가 실제로 가져온 URL** (+ 연 페이지, 본문 인용) | `dropped hotel not in search sources` |
| 상세 주소인가 | 확인한 상세 꼴 ([`isHotelDetailUrl`](../src/modules/hotel/search-url.ts)) | 목록·검색 페이지는 버린다 |
| 그 호텔인가 | 상세 페이지 `og:title`/`<title>` 에 호텔명의 의미 있는 단어가 있나 | `dropped hotel name mismatch` |
| 같은 호텔인가 | 영문 병기 이름 (사이트마다 한글 표기가 흔들린다) | 앞 갈래 것만 남긴다 |

> ⚠️ **출처가 비어 오면 대조를 건너뛴다.** 툴 버전이 출처를 안 주면(`search returned no sources`) 대조할 근거가 없다. 거기서 전부 버리면 툴 하나 바뀐 것에 검색이 죽는다. 로그의 `hotel search … sources=N grounded=M` 에서 `sources=0` 이 이어지면 이 경로다.

> ⚠️ **페이지를 못 읽으면 이름 확인 없이 남긴다.** 호텔스닷컴(429)·클룩(403)은 봇을 자주 막는다. 확인한 수는 trace 의 `namesVerified` 다.

> ⚠️ **20곳을 못 채워도 채우지 않는다.** 찾은 만큼만 낸다. 0곳이면 우리가 만든 지역 검색 링크(⑥)가 나간다.

**비용:** 1차가 갈래 둘이라 검색 호출이 1회에서 2회로 늘었다. 동시에 돌아서 시간은 한 번과 비슷하다.

**왜 두 번 부르나** — 한 번에 시키면 모델이 검색 결과를 요약하는 데 힘을 쓰고 비교·선별은 대충 한다.

> ⚠️ **두 호출 다 구조화 출력을 건다.** 1차를 자유 텍스트로 뒀더니 모델이 "웹 검색을 진행해도 될까요? 날짜를 알려주세요" 라고 되묻고 끝나서 후보가 0개가 됐다. 상대는 사람이 아니라 프로그램이라 그 질문에 답할 사람이 없다.

> ⚠️ **1차는 `tool_choice: required` 다.** `auto` 로 두면 모델이 검색을 건너뛰고 기억으로 답한다. 실측으로 같은 질의에 어떤 때는 웹을 20번 뒤지고, 어떤 때는 5초 만에 빈 배열을 뱉었다.

> ⚠️ **후보가 0개면 2차를 부르지 않는다.** 빈손에서 고르라고 하면 모델이 없는 호텔을 지어낸다.

### 예약 링크 — 트립닷컴만 인정한다

```
trip.com
```

**왜 한 곳인가 — 날짜·인원이 살아서 가는 곳이 여기뿐이다** (2026-11-10).

| 제휴몰 | 상태 | 근거 |
|---|---|---|
| **트립닷컴** | ⭕ 쓴다 | 애드픽을 거쳐도 날짜·인원이 유지되는 것을 실측했다 |
| 호텔스닷컴 | ❌ 뺐다 | 애드픽 → Partnerize 경유에서 쿼리가 날아간다 ([ISSUE 문서](./ISSUE-2026-11-09-HOTELS-COM-STAY.md)) |
| 마이리얼트립 | ❌ 뺐다 | 제휴 링크가 「서비스 정책에 의해 링크 연결이 차단」으로 막혔다 (2026-11-09) |
| 클룩 | ❌ 뺐다 | 애드픽 경유 확인을 한 적이 없다. 호텔 상세가 검색에 잘 안 걸려 갈래도 없었다 |

> ⚠️ **줄 수보다 고지가 비싸다.** 날짜가 안 가는 줄이 하나라도 섞이면 그 카드는 날짜를 아예 말하지 못한다(`stayReachesUser`). 멀쩡한 트립닷컴 줄까지 「반영되지 않았어요」를 달고 나가므로, 줄 수를 늘리자고 섞는 것은 남는 장사가 아니다.
>
> **저장된 행에서도 뺀다** — `HotelService.isItem` 이 **허용 목록**으로 판정한다(차단 목록이 아니라). 캐시는 하루를 살아서, 여기서 안 거르면 뺀 제휴몰 줄이 갱신 전까지 계속 나간다. 주소 형식은 확인해둔 것이라 `DETAIL_FORMATS` 에 남아 있다 — 다시 켜려면 `ALLOWED_HOSTS`·`SITE_BRANCHES` 에 넣으면 된다. 항공권은 별개다.
>
> ⚠️ **검색 링크 카드(⑥)만 아직 호텔스닷컴이다.** 트립닷컴 검색 주소는 지역을 내부 숫자 ID 로 받아서 우리가 만들 수 없다(`SEARCH_MERCHANTS`). 그 줄은 날짜·인원도 애드픽 경유에서 날아갈 것이므로 **설명에 날짜를 적지 않는다.**

모델은 없는 URL 을 그럴듯하게 만들어낸다. 그게 애드픽 변환을 타고 나가면 404 로 떨어진다. 호스트라도 걸러서 피해를 줄인다 — 목록 밖 링크(아고다·부킹닷컴)는 **버린다**.

**한국어 페이지를 강제한다.** 프롬프트로 시키고(`kr.trip.com`), 그게 안 먹었을 때를 위해 [`toKoreanUrl()`](../src/common/booking-url.ts) 이 마지막 방어선으로 호스트·쿼리를 고친다. 영문 페이지가 뜨면 사용자는 예약까지 못 간다.

### 썸네일 — 모델에게 안 받는다

```
① 모델이 준 주소      거의 없다 (1차 스키마에 이미지 필드가 없고 web_search 는 텍스트만 준다)
② 예약 페이지 긁기    og:image → ld+json → 본문 <img>    ← 실질적인 경로
③ 살아 있는지 확인    HEAD → 막히면 Range GET 1KB
```

> ⚠️ **og:image 라고 다 쓰면 안 된다.** 사이트들은 상세 페이지에도 공용 로고를 og:image 로 박아둔다 (마이리얼트립의 `mrt_main_og_image.png` 를 실제로 받았다). 그대로 쓰면 호텔 다섯 줄이 전부 같은 로고가 된다 — **이미지가 없는 것보다 나쁘다.** 걸리면 아래층으로 내려간다.

CDN 마다 사정이 다르다. trip.com CDN 은 **HEAD 에 content-type 을 안 준다** — 없다고 버리면 이미지를 다 놓친다. 그래서 타입을 안 알려주면 200 을 믿는다.

페이지를 읽을 땐 **브라우저 UA 를 보낸다.** 안 보내면 hotels.com 이 403·429 를 준다. 본문은 앞부분 몇백 KB 만 읽는다 — 예약 페이지는 200~400KB 인데 이미지 주소는 앞쪽에 있고, 5곳을 동시에 읽기 때문이다.

**사진을 못 구했다고 호텔을 빼지는 않는다.** 그 줄만 사진 없이 나간다.

### 중복 제거 — `sourceUrl` 기준

AI 는 같은 호텔을 이름만 다르게 여러 번 준다('호텔 그란비아 오사카' / 'Hotel Granvia Osaka'). 이름은 못 믿으므로 예약 주소로 판정한다. **저장 전에** 지운다 — 저장 후에 지우면 20건이 페이지마다 줄고, 2페이지에 1페이지에서 본 호텔이 다시 나온다.

## 6. 캐시와 비용

| 무엇 | 어디 | TTL |
|---|---|---|
| 검색 결과 20건 | `search_results` + 프로세스 메모리 | **24시간** |
| 실패·빈손 | 같음 (`status='failed'`) | 10분 |
| 발화 해석 | `intent_cache` + 메모리 | 7일 |
| 지역 별칭 | `place_aliases` + 메모리 | 없음 |
| 애드픽 링크 | `affiliate_links` | 30일 |

캐시 키는 **`hotel:{place_id}`** — 도시 문자열이 아니라 지역 ID 다. 표기가 갈리면(`오사카`/`osaka`/`오사카시`) 같은 도시를 물어도 AI 가 새로 돌기 때문에, [`place_aliases`](../src/modules/places/places.service.ts) 가 이걸 한 ID 로 모은다.

**날짜·인원은 키에 없다.** 넣으면 캐시가 거의 안 맞아 매 질문이 AI 호출이 된다. 목록에 반영하지 않았다는 사실을 카드 아래에 반드시 적고, 날짜·인원은 **링크를 그릴 때** 그 사람의 발화에서 다시 읽어 넣는다([`withStay`](../src/modules/hotel/search-url.ts)).

> ⚠️ **조건이 박힌 주소가 곧 애드픽 변환 키다.** 날짜가 바뀌면 커미션 링크도 새로 만들어진다. 기본값으로 여는 사람은 하루 동안 같은 키라 캐시를 맞지만, 날짜를 직접 말한 사람의 첫 클릭은 변환을 기다린다(`ADPICK_CLICK_TIMEOUT_SECONDS`, 넘기면 원본 주소로 간다).
>
> **단 추적 코드(`p_data`)는 안 갈린다.** 리다이렉트가 [`withoutStay`](../src/modules/hotel/search-url.ts) 로 조건을 뗀 주소를 같이 넘기고, 코드는 그걸로 만든다 — 조건마다 갈리면 애드픽 성과 화면에서 **같은 호텔이 수십 줄로 쪼개지고**, 전환은 드물어서 한 줄에 0 아니면 1 이 찍힌다. 날짜별로 봐야 하면 `recommendation_items.source_url` 에 조건이 그대로 남아 있다.

### 동시 호출 방지 (single-flight)

캐시가 빈 상태에서 세 명이 동시에 "오사카 호텔"을 치면 **먼저 꽂은 하나만** 검색한다. 프로세스 안에서는 Map 에 동기적으로, 프로세스 밖으로는 `insert ... on conflict do nothing` 으로 가른다. 나머지는 "먼저 찾고 있어요" 를 받는다.

### 빈손은 한 번으로 굳히지 않는다

모델은 같은 질의에도 가끔 빈손으로 돌아온다. 한 번에 10분을 굳히면 그게 그대로 10분짜리 장애가 된다 — "도쿄 호텔"이 실제로 그랬다. **연속 두 번**이어야 진짜 없는 것으로 보고, 첫 번째는 1분만 굳힌다.

### 애드픽 rate limit

분당 **60회**(`linkonly=true`)다. 호텔 5건이면 캐시 미스 시 요청 하나에 5회를 쓴다. 그래서 **페이지를 자른 뒤에** 변환한다 — 이번 카드에 안 나갈 호텔까지 변환하면 한도를 헛되이 쓴다.

## 7. DB 에 남는 것

```
recommendations        추천 1회 (도메인·지역·provider·소요시간·캐시히트 여부)
recommendation_items   노출된 줄 (호텔명·clickId·원본주소·최종목적지·클릭 카운터
                       + 1박가·판매처·썸네일·제휴링크 — 0013 에서 한 테이블로 합쳤다)
affiliate_links        sourceUrl → 커미션 링크 (30일 캐시)
messages               발화 원문
```

**호텔 마스터 테이블이 없다.** 이름으로는 "같은 호텔"을 못 묶기 때문이다. 호텔의 신원은 `source_url` 이고, `affiliate_links` 가 `(partner, source_url)` 유니크로 그 역할을 겸한다.

클릭은 행이 아니라 **카운터**다. 같은 줄을 10번 눌러도 `recommendation_items.click_count` 가 10이 된다. 노출과 클릭이 한 행에 있어 CTR 이 join 없이 나오고, 리다이렉트 DB 왕복이 1회로 끝난다.

**변환 실패는 경고로 남는다.** 목적지가 원본과 같으면 커미션 링크가 아니라는 뜻이고, 세지 않으면 "링크는 열리는데 수수료가 안 들어온다"를 영영 못 찾는다.

## 9. 확인하는 방법

```bash
# ① 해석만 — 싸고 빠르다. "왜 도움말이 나오지?" 를 가릴 때 여기부터
curl -s localhost:8000/api/v1/debug/parse \
  -H 'content-type: application/json' -H "X-Debug-Token: $DEBUG_TOKEN" \
  -d '{"utterance":"오사카 호텔 4명 9월 22~24일 추천해줘"}' | jq

# ② 전체 파이프라인 (동기, 7~30초, OpenAI 요금)
#    캐시를 읽지도 쓰지도 않고, 통계도 남기지 않는다.
curl -s localhost:8000/api/v1/debug/search \
  -H 'content-type: application/json' -H "X-Debug-Token: $DEBUG_TOKEN" \
  -d '{"utterance":"오사카 호텔 추천해줘"}' | jq '.response'
```

②는 **사용자에게 실제로 배달될 말풍선을 그대로** 돌려준다. 카드 조립은 운영과 같은 코드를 태운다.

라우터는 5초 예산 때문에 검색을 백그라운드로 던지므로, 스킬 응답만 봐서는 검색 성공 여부를 알 수 없다 — 늘 "찾고 있어요"다. 그래서 이 엔드포인트가 있다.

```bash
# 로그에서 이 검색만 보기
docker compose logs -f app | grep 'hotel search city=오사카'
```

```
hotel search city=오사카 searches=3 candidates=28 chars=4210 ms=12400
hotel rank city=오사카 picks=20 ms=6100
```

`searches=0` 이면 모델이 웹을 안 뒤지고 기억으로 답한 것이다 — URL 과 가격이 특히 위험하다.
