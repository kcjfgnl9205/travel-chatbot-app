| 설정 | 값 | 위치 |

예산을 넘기면 [router.controller.ts:195](../src/modules/kakao/router.controller.ts#L195) 가 하던 일을
버리고 `notUnderstoodCard` 를 보낸다. 그게 테스트 내내 나온 **"어떤 여행을 찾으시나요?"** 다.

넘기는 길이 둘이다.

- **콜드 DB** — 왕복 7회 × 730ms = **약 5.1초**. 모델을 안 타도 넘긴다.
- **모델 해석** — 타임아웃 4초가 **예산 3.5초보다 길다.** 모델을 타면 그것만으로 끝난다.

그래서 **같은 질문이 처음엔 실패하고 다시 하면 된다.** 두 번째에는 메모리 캐시·검색 캐시가
따뜻해져 DB 왕복이 줄기 때문이다. 요청서의 *"나중에 다시 테스트했을 때 정상"*(2번),
*"짧게 다시 입력하자 결과가 나왔다"*(4번), *"다른 테스트에서는 정상적으로 되묻기도 했다"*(5번)가
전부 이 현상이다.

> ⚠️ **파서 문제가 아니다.** "부산 관광지 추천해줘"를 실제로 돌려보니 모델 없이 0ms 에
> `attraction/부산` 으로 정상 해석된다. "부산 관광지"와 **완전히 같은 경로**다.
> 둘의 차이는 해석이 아니라 **그 시점에 캐시가 따뜻했는가**뿐이다.

## 1. 요청 항목별 답변

### 1. AI가 찾은 링크가 404면 아예 안 보이게 — 🟢 **가능**

**가능하다.** 호텔 검색은 백그라운드(7~30초)라 응답 예산과 무관해서, 저장 전에 링크를
한 번 열어보고 죽은 줄을 버릴 여유가 있다.

필요한 것도 이미 있다 — [booking-url.ts](../src/common/booking-url.ts) 의 `chooseUrl` 이
그 판정을 하는 함수인데 **아무도 안 부른다.** 호텔 provider 가 re-export 만 하고 끝이다.

**주의 두 가지** (여기를 틀리면 지금보다 나빠진다)

- **404·410만 버린다.** 이 사이트들은 봇을 막아서 403·429를 자주 주는데, 그건 "주소가
  틀렸다"가 아니라 "우리가 봇으로 보인다"는 뜻이다. 그걸 근거로 버리면 **멀쩡한 줄이
  전부 사라진다.** `chooseUrl` 주석에 이미 같은 경고가 적혀 있다.
- **전부 버려지면 카드가 빈다.** 지금도 허용 호스트 밖이라고 19/20이 떨어진 적이 있다
  ([openai.provider.ts:294](../src/modules/hotel/providers/openai.provider.ts#L294) 부근 로그).
  링크 검증까지 더하면 빈손이 늘어난다 → **지역 검색 링크 폴백이 같이 가야 한다**
  (요청서 1번의 *"지역 검색 링크라면 오사카 호텔 검색 결과가 나와야 합니다"*가 이 자리다).

> 그래서 1번은 **3·8번(플랫폼 검색쿼리)과 같이 처리하는 게 맞다.** 폴백으로 쓸
> "오사카 호텔 검색 결과" 주소를 만들 수 있어야 하기 때문인데, **그 주소는 이제 만들 수 있다**
> — 호텔스닷컴이 지역을 이름으로 받는다(§3·8).

**아직 못 가린 것** — 홈으로 튕기는 게 ① 모델이 지어낸 URL 때문인지 ② 애드픽 변환이
딥링크를 버려서인지 모른다. ②라면 링크 검증으로 안 고쳐진다(변환 후 주소가 바뀌므로).
카드 하나를 뽑아 `원본 → 애드픽 링크 → 최종 도착지`를 따라가 보면 한 번에 갈린다.

### 2. 간헐적으로 정보를 못 불러오는 이유 — 🟡 **원인 확인됨, 일부만 제거 가능**

실패 지점이 **셋**인데 지금은 **전부 같은 문구**로 나간다. 이것부터 갈라야 한다.

| # | 실패 지점 | 사용자가 보는 것 | 고칠 수 있나 |
|---|---|---|---|
| ① | **응답 예산 3.5초 초과** (위 §0) | "어떤 여행을 찾으시나요?" | 🟢 가능 |
| ② | 모델이 **허용 호스트 밖 링크만** 줘서 전량 탈락 | "정보를 지금은 정리하지 못했어요" | 🟡 완화만 |
| ③ | 검색 타임아웃 (`SEARCH_TIMEOUT_SECONDS`=240초) | "불러오지 못했어요" | 🟡 완화만 |

②가 "부산 호텔"의 정체로 보인다. 허용 목록은 트립닷컴·마이리얼트립·클룩·호텔스닷컴
**네 곳뿐**인데, 국내 호텔은 이 넷의 한국어 페이지 커버리지가 해외만 못하다. 모델이
야놀자·여기어때·아고다를 물어오면 **전부 버려지고 0건**이 된다
([openai.provider.ts](../src/modules/hotel/providers/openai.provider.ts) `toHotels`).

> 로그에 `hotel normalize city=부산 picks=20 kept=0 ... hosts=` 가 남는다.
> **서버 로그만 보면 ②인지 ③인지 바로 갈린다.** 재현되면 그 줄을 보내주시면 확정된다.

**모델 품질에 달린 부분이라 "항상 나온다"는 보장은 못 한다.** 대신 요청서의
*"일시적으로 보여줄 수 없다면 상황에 맞는 재시도 안내"* 는 충족할 수 있다.

**추가로 바로 고칠 것 하나** — [cards.ts:366](../src/modules/kakao/cards.ts#L366)

```ts
function narrowerHint(meta: SearchMeta): string {
  if (meta.kind === 'flight') return '';
  return '동네 이름을 붙여 말해도 좋아요 (예: 도쿄 신주쿠).';   // ← 고정 문구
}
```

빈손이면 **무조건** 붙는다. 이미 "도쿄 신주쿠"라고 말한 사람도 똑같이 받는다.
게다가 그 예시대로 치면 3번 문제로 또 실패한다 — **봇이 권한 예시가 봇에서 안 된다.**
→ 지역 종류(`place.kind`)가 `area`/`landmark` 면 이 문장을 빼면 끝난다.

### 3·8. 상세 지역 / 날짜 — 플랫폼 검색쿼리로 — 🟢 **가능 (URL 검증 완료)**

> **요청**: 해운대·신주쿠 근처 호텔 검색 가능? 항공권처럼 각 플랫폼 검색쿼리 쓰면 안 되나?

**방향이 정확하다.** 항공권이 이미 그 길로 갔다 — `f4e28a5`("항공권은 검색하지 않는다")가
AI 검색을 통째로 걷어내고 IATA 코드로 주소를 조립하게 바꿨고
([link-offers.ts](../src/modules/flight/link-offers.ts)), 그래서 항공권은 **즉답·0원·빈손 없음**이다.
같은 글에 *"날짜·인원을 반영할 수 있다"* 고 적혀 있다 — **8번이 항공권에서는 이미 풀린 문제다.**

호텔에 그대로 옮기면 1·2·3·8이 한꺼번에 해결된다. 주신 주소 4건으로 **어디까지 되는지가 갈렸고, 두 곳은 검증까지 끝났다.**

#### 검색 URL 확인 결과 (2026-11-02, 실제 주소창 복사본 4건)

받은 주소를 파라미터로 풀어본 결과 **두 갈래로 갈린다.**

| 플랫폼 | 지역 지정 방식 | 지금 조립 가능? |
|---|---|---|
| **호텔스닷컴** | `destination=오사카` — **이름 그대로** | 🟢 **가능** |
| **마이리얼트립** | `keyword=오사카` + `regionId=2225` | 🟡 keyword 단독 여부 확인 필요 |
| 클룩 | `city_id=29` · `svalue=29` — **내부 숫자 ID** | 🔴 대조표 없이는 불가 |
| 트립닷컴 | `city=219` · `searchValue=19\|219*19*219*1` — **내부 복합 ID** | 🔴 대조표 없이는 불가 |

```
호텔스닷컴  destination=오사카  startDate/endDate(=d1/d2)  adults  rooms
마이리얼트립 keyword=오사카  regionId=2225  checkIn/checkOut  adultCount  roomCount
클룩        city_id=29  svalue=29  (title·override 는 화면 라벨일 뿐)
트립닷컴     city=219  provinceId=11088  countryId=78  searchValue=19|219*19*219*1
```

**호텔스닷컴이 결정적이다.** 지역을 이름으로 받으므로 우리가 들고 있는 한국어 지명을
그대로 넣으면 된다 — **대조표가 필요 없다.** 앞서 "플랫폼 내부 ID 때문에 어렵다"고 본
걸림돌이 적어도 한 곳에서는 없다.

클룩·트립닷컴은 `오사카 → 29`, `오사카 → 219` 같은 **도시 ID 대조표**를 우리가 만들어야 한다.
사람이 한 번 채워 넣으면 되는 일이지만(항공권 `TRIP_CITY_CODES` 와 같은 모양),
**세부 지역(해운대·신주쿠)까지 ID 를 구할 수는 없다** — 그래서 3번의 답은 호텔스닷컴 쪽이다.

#### 그래서 이렇게 하면 된다

1. **호텔스닷컴으로 먼저 붙인다.** 이름 기반이라 `destination=해운대`, `destination=신주쿠` 가
   그대로 들어간다. **3번(상세 지역)이 여기서 풀린다.**
2. **1번의 "지역 검색 링크 폴백"도 같은 주소를 쓴다.** 404 로 버린 줄 자리에 이걸 넣으면
   *"지역 검색 링크라면 오사카 호텔 검색 결과가 나와야 합니다"* 가 충족된다.
3. 마이리얼트립은 `keyword` 단독으로 되는지 확인되면 둘째 줄로 붙인다.
4. 클룩·트립닷컴은 대조표를 채우는 만큼만 붙인다. 없으면 그 줄을 안 만든다
   (항공권이 공항 코드를 모르면 줄을 안 만드는 것과 같다).

#### ✅ 검증 완료 (2026-11-02)

덜어낸 주소 두 개가 **브라우저에서 정상 동작하는 것을 확인했다.**

```
https://kr.hotels.com/Hotel-Search?destination=해운대&d1=…&startDate=…&d2=…&endDate=…&adults=2&rooms=1
  → 추적 GUID(typeaheadCollationId) 없이 동작한다. **세부 지역("해운대")도 이름으로 걸린다.**

https://accommodation.myrealtrip.com/union/products?keyword=오사카&checkIn=…&checkOut=…&adultCount=2&childCount=0&roomCount=1&isDomestic=false
  → regionId 없이 keyword 단독으로 동작한다.
```

**두 플랫폼은 대조표 없이 지금 조립할 수 있다.** 줄 두 개면 폴백으로도, 상세 지역 검색으로도
충분하다. 클룩·트립닷컴은 내부 ID 대조표를 채우는 만큼만 나중에 붙이면 된다.

| 플랫폼 | 조립 | 쓸 수 있는 칸 |
|---|---|---|
| 호텔스닷컴 | 🟢 **확인됨** | 지역(이름·세부 지역) · 체크인/아웃 · 인원 · 객실 |
| 마이리얼트립 | 🟢 **확인됨** | 지역(keyword) · 체크인/아웃 · 인원 · 객실 |
| 클룩 | 🔴 `city_id` 대조표 필요 | 〃 |
| 트립닷컴 | 🔴 `city`·`searchValue` 대조표 필요 | 〃 |

#### 💰 예산(가격) 필터 — **범위에서 제외** (2026-11-02 결정)

받은 주소 네 건에 가격 파라미터가 없었고, **가격 필터는 안 해도 된다는 결정을 받았다.**

→ 8번의 *"지원하기로 한 조건은 결과에 반영"* 중 **날짜·인원·객실만 반영하고 예산은 안 한다.**
그러면 8번의 나머지 요구가 그대로 살아난다 — *"미지원 조건은 사용자가 입력하기 전에도
알 수 있도록 안내"*. 즉 **예산은 계속 "반영되지 않았어요" 로 고지하고, 도움말에서도
예산은 못 받는다고 밝힌다.**

⚠️ 도움말 본문은 이 저장소에 없다(오픈빌더 설정). [KAKAO-SETUP.md §5](KAKAO-SETUP.md) 의
권장안에는 `· 날짜·인원은 아직 검색에 반영되지 않아요` 가 있는데 — **이제 이 문장이
거꾸로 틀리게 된다.** 날짜·인원은 반영되고 예산만 안 되기 때문이다. 권장안을 이렇게 바꾼다.

```
· 호텔 예산(1박 10만원 이하 등)은 아직 반영되지 않아요
```

#### ⚠️ 3번은 반쪽이 더 있다 — 해석도 같이 고쳐야 한다

위는 **링크** 이야기다. 그 전에 **발화를 제때 해석하는 문제**가 남아 있다.

지역 해석 자체는 이미 세부 지역을 지원한다("도시가 아니어도 그대로 둔다"가 설계이고
`place.kind` 에 `area`/`landmark` 가 있다). `5f7d926` 이 **"도쿄 신주쿠"가 도쿄로 검색되던
문제**를 이미 고쳤다. 3번이 실패한 건 해석이 아니라 **그 경로가 모델을 타서 예산을 넘긴 것**이다(§0).

→ **세부 지역을 사전에 넣으면 모델 왕복이 사라져 0ms 가 된다.** 해운대·신주쿠·시부야·난바처럼
자주 나오는 곳부터 [city-table.ts](../src/modules/places/city-table.ts) 에 줄을 추가하는 일이다.
URL 조립과 **둘 다 해야** 3번이 끝난다.

#### 8번의 "1박" 분류 — 🟢 **1줄로 가능**

[cards.ts:308](../src/modules/kakao/cards.ts#L308) 의 `conditionLabel` 정규식이
`\d+\s*(월|일|박|\/)` 로 **"박"을 날짜 쪽에 넣고 있다.** 그래서 "날짜·예산(1박, 10만원)".
`박` 을 빼고 가격 쪽으로 옮기면 끝난다.

> 예산을 안 받기로 했으므로 **"예산(10만원)은 반영되지 않았어요" 고지는 계속 나간다.**
> 다만 "1박" 이 날짜로 분류되면 **날짜는 반영되는데도 "날짜가 반영 안 됐다"** 고 하게 되어
> 거짓말이 된다. 그래서 이 한 줄이 URL 조립과 **같이** 가야 한다.

### 4. "부산 관광지 추천해줘"도 되게 — 🟢 **가능 (파서는 이미 통과)**

```
"부산 관광지"          → 사전 경로 0ms → attraction / 부산   ✅  (완전히 같다)
```

**해석은 이미 된다.** 실패는 §0의 예산 초과다. 예산을 고치면 4번은 같이 해결된다.

### 5. 대화 이어가기 — 🟢 **가능. 사용자 ID 기반 구조가 이미 있다**

> **요청**: `@챗봇 제주관광지 추천해줘` 로 다시 안 치고 이어서 되나? 사용자 id 있으니 가능한가?

**가능하다. 물어보신 그 구조가 이미 들어 있다.**
[pending.ts](../src/modules/kakao/pending.ts) 의 `PendingAskMemory` 가 **사용자별로 5분간**
"무엇을 되물었는지"를 들고 있고, 단톡방이라 사람마다 따로 관리하는 것까지 돼 있다.
`userKey` 는 [skill-payload.dto.ts:63](../src/modules/kakao/dto/skill-payload.dto.ts#L63) 의
`botUserKey` 다.

**문제는 그걸 쓰는 걸 한 군데서 빠뜨린 것이다.**
[router.controller.ts:262](../src/modules/kakao/router.controller.ts#L262), [L268](../src/modules/kakao/router.controller.ts#L268)

```ts
if (!parsed.place) return cards.askPlaceCard(parsed.intent, req.botName);
...
if (!place)       return cards.askPlaceCard(parsed.intent, req.botName);
```

**묻기만 하고 `pending.remember()` 를 안 부른다.** 그래서 다음에 "제주"가 오면

1. `looksLikePlaceName("제주")` → true
2. `pending.take()` → **null** (저장한 적이 없다)
3. `TRAVEL_HINT.test("제주")` → **false** ("제주"엔 여행 신호가 없다)
4. → `notUnderstoodCard`

"다른 도시" 버튼 경로([L221](../src/modules/kakao/router.controller.ts#L221))와 나라 되묻기
([L278](../src/modules/kakao/router.controller.ts#L278))는 `remember` 를 제대로 부른다.
**이 두 줄만 빠졌다.**

> 되묻는 것 자체가 가끔만 나온 이유도 설명된다 — 되묻기는 모델이 제때 답했을 때만 나오고(§0),
> 되물은 뒤 "제주"는 **언제나** 실패한다.

**멘션은 여전히 필요하다.** 단톡방은 봇을 멘션한 메시지만 서버로 오기 때문에
`@가자고 제주` 까지는 쳐야 한다. 대신 **"제주" 한 단어면 되고 "관광지 추천해줘"는 안 쳐도 된다.**
멘션은 `mention` 버튼이 입력창에 넣어준다.

### 6·7. 날짜가 잘못됐을 때 다시 입력 가이드 — 🟢 **가능. 단 날짜 선택 버튼은 없다**

#### 먼저 — 버튼 기능 확인 결과

**카카오 스킬 응답에 날짜 선택(datepicker) 버튼은 없다.** 공식 문서 기준 버튼 `action` 은
`webLink` · `message` · `block` · `phone` · `share` · `operator` **여섯 개뿐**이고,
날짜/달력 관련 입력 액션은 없다. 날짜를 다루는 건 발화에서 날짜를 뽑는 `sys.date` 엔티티뿐이다.

게다가 **팀채팅 챗봇은 QuickReplies 를 아예 지원하지 않는다**
([templates.ts](../src/modules/kakao/templates.ts) 주석, 그룹 챗봇 beta 가이드 표 3).

→ **쓸 수 있는 건 `action: "message"` 버튼 하나다.** 누르면 그 문장이 그대로 발화로 전송된다.
   이미 나라 되묻기에서 쓰고 있는 방식이다([cards.ts](../src/modules/kakao/cards.ts) `askCityInCountry`).

#### 그래서 이렇게 된다

날짜가 잘못되면 **후보 날짜를 버튼 2~3개로 제시**한다.

```
⚠️ 귀국일(11월 20일)이 출발일(11월 23일)보다 빨라요.
   [11월 26일 귀국]  [11월 30일 귀국]  [직접 입력]
```

누르면 `서울에서 도쿄 항공권 11월 23일 출발 11월 26일 귀국` 이 그대로 전송된다.
달력은 못 띄우지만 **한 번 눌러서 고칠 수 있다.**

#### 6번 — 원인 확정

[search-url.ts:106](../src/modules/flight/search-url.ts#L106)

```ts
if (back && back < depart) back = fallbackBack;   // fallbackBack = 출발일 + 7일
```

11월 23일 + 7일 = **11월 30일**. 요청서 숫자와 정확히 같다.

이 코드는 `55010d0`("다음주 수요일~금요일"이 10/21 출발 10/16 귀국으로 나갔다)의 대응이다.
**파서가 틀린 경우**를 구제하려던 건데, 사용자가 **직접 말한 날짜**까지 같이 덮는다.
→ `TripParams` 에 "사용자가 직접 말했는가"를 남기고, 직접 말한 경우에만 되묻는다.

#### 7번 — 원인 확정

[trip-params.ts:227](../src/modules/flight/trip-params.ts#L227)

파서에 **연도 패턴이 아예 없다.** `2026년` 은 어떤 정규식에도 안 걸려 버려지고,
남은 `10월 20일` 이 *"지났으면 내년"* 규칙을 타 **2027년**이 된다.

규칙 자체는 맞다("1/5"를 10월에 말하면 내년 1월). 문제는 **연도를 말한 사람에게도 적용**하는 것.
→ `(\d{4})\s*년` 을 추가하고, 연도를 명시했으면 굴리지 않고 과거라고 알린다. 6번과 같은 버튼을 쓴다.

### 9. 애드픽 링크가 있으면 제휴 안내 추가 — 🟢 **가능 (문구 확정됨)**

**확인한 사실** — 사용자에게 보이는 코드 어디에도 광고·제휴·수수료 문구가 없다.
카드 아래 안내를 만드는 `noticeText`([cards.ts:290](../src/modules/kakao/cards.ts#L290))는
반영 안 된 조건과 출발지 추정만 적는다. **요청서 내용이 맞다.**

**"애드픽 링크가 포함되어 있으면"을 코드로 판정할 수 있다** — 이미 그 정보를 들고 있다.

```ts
// adpick.service.ts
export const ADPICK_UNSUPPORTED_MERCHANTS = ['skyscanner'];
export function adpickCarries(merchant) { ... }
```

→ 카드 줄 중 `adpickCarries(merchant)` 가 참인 게 하나라도 있으면 문구를 붙인다.
스카이스캐너만 있는 항공권 카드에는 안 붙는다.

**붙는 위치** — 새 말풍선은 못 만든다. 카드 + 고지 + 멘션 버튼이 **이미 3개로 꽉 차서**
하나 더 얹으면 `MAX_OUTPUTS` 에서 잘려 멘션 버튼이 조용히 사라진다
([templates.ts](../src/modules/kakao/templates.ts)). → **기존 고지 말풍선에 한 줄로 합친다.**

#### 문구 확정 (2026-11-02)

```
본 검색 결과에는 제휴 업체가 포함되어 있습니다.
```

**21자라 길이 문제는 없다.** 기존 고지(날짜 미반영 · 출발지 추정) 아래 한 줄로 붙인다.

```
날짜·예산(1박, 10만원)은 반영되지 않았어요.
본 검색 결과에는 제휴 업체가 포함되어 있습니다.
```

판정 규칙 — 카드 줄 중 `adpickCarries(merchant)` 가 참인 게 **하나라도** 있으면 붙인다.

| 카드 | 붙나 |
|---|---|
| 호텔 (트립닷컴·마이리얼트립·클룩·호텔스닷컴) | ✅ |
| 항공권 (트립닷컴·마이리얼트립 줄이 있음) | ✅ |
| 항공권이 스카이스캐너 줄만 남은 경우 | ❌ (애드픽 광고주 아님) |
| 관광지 | ❌ (제휴 단계가 없다) |

> 관광지에 안 붙이는 건 코드 구조상 저절로 그렇게 된다 —
> 관광지는 제휴 모듈을 아예 안 쓴다([recommendation.module.ts](../src/modules/recommendation/recommendation.module.ts)).
> 다르게 원하시면 알려주세요.

## 2. 수정 내역

### 공통 — 응답 예산을 넘겨도 답을 버리지 않는다 [2·3·4·5·10]

[router.controller.ts](../src/modules/kakao/router.controller.ts) `withinBudget`

예전에는 예산(3.5초)을 넘기면 하던 일을 **통째로 버리고** 도움말 카드를 보냈다.
이제는 갈린다.

| 상황 | 응답 |
|---|---|
| 콜백 켜짐 | `useCallback` 으로 끊고, 늦게 끝난 답을 **콜백으로 민다** |
| 콜백 꺼짐 | `slowText` — "아직 정리 중이에요. 잠시 뒤 다시 보내주시면 바로 보여드릴게요" |

⚠️ **늦은 답이 `useCallback` 이면 밀지 않는다.** 검색 미스라 백그라운드가 이미 밀기로
예약한 경우다 — 콜백 URL 은 1회용이라 둘이 같이 쏘면 하나가 버려진다.

> **예산 값은 안 올렸다.** 3.5초를 4.5초로 올리면 카카오의 5초 벽에 여유가 거의 없어진다.
> 파싱 타임아웃(4초)도 안 내렸다 — 코드에 *"2.5초는 너무 빡빡했다"* 는 측정 기록이 있다.
> 대신 **모델을 타는 경우 자체를 줄였고**(아래 세부 지역 사전), 넘겨도 안 죽게 만들었다.

  `HOTEL_VERIFY_LINKS=false` 로 끌 수 있다.

### 6·7 · 날짜

- **연도를 읽는다** — `YEAR_MONTH_DAY` · `YEAR_RANGE`. 연도를 적었으면 굴리지 않는다.
- **고치지 않고 되묻는다** — `TripParams.problem` 에 표시하고
  [search.service.ts](../src/modules/search/search.service.ts) `serve` 가 **검색 전에** 끊는다.
  (검색까지 가면 날짜가 틀려도 캐시는 채워져 다음 사람이 그 행을 받는다)
- **`explicit` 로 가른다** — 직접 적은 날짜만 되묻는다. 상대 표현("다음주 수요일~금요일")을
  파서가 잘못 읽은 것은 예전처럼 조용히 고친다. 사용자는 그런 날짜를 말한 적이 없다.
- **버튼은 `message`** — 카카오에 날짜 선택 버튼이 없다. 후보를 눌러 보내는 것이 유일한 길이고,
  **messageText 에 연도를 박는다** (안 박으면 그 문장이 또 굴러간다).

```
귀국일(11월 20일)이 출발일(11월 23일)보다 빨라요
 • 11월 20일 출발 · 11월 23일 귀국   → "…2026년 11월 20일 출발 2026년 11월 23일 귀국"
 • 11월 23일 출발 · 11월 26일 귀국   → "…2026년 11월 23일 출발 2026년 11월 26일 귀국"
```

### 8 · 호텔 조건

- `conditionLabel` 에서 **"1박" 을 날짜가 아니라 예산으로** 분류한다.
- 도움말을 실제 범위에 맞췄다 — [KAKAO-SETUP.md §5](KAKAO-SETUP.md). 예산 미지원을 명시하고,
  **예시를 실제로 동작하는 것으로 바꿨다**(부산 해운대 호텔 등). 6장 체크리스트에
  "도움말 예시를 그대로 쳐본다" 를 넣었다.
- ⚠️ **오픈빌더 설정은 사람이 직접 바꿔야 한다.** 저장소 문서는 권장안일 뿐이다.

### 9 · 제휴 고지

```
본 검색 결과에는 제휴 업체가 포함되어 있습니다.
```

- 기존 고지 말풍선에 **한 줄로 합친다.** 새 말풍선을 만들면 `MAX_OUTPUTS`(3)에서
  멘션 버튼이 조용히 잘린다.
- 판정은 `adpickCarries(merchant)` — 리다이렉트가 쓰는 **같은 함수**다. 두 곳이 각자
  기억하면 언젠가 갈린다.
- 스카이스캐너만 남은 항공권 카드와 관광지에는 안 붙는다.

## 3. 남은 것

### 배포 후 확인할 것

1. **도움말 블록 수정** — 오픈빌더 설정이라 코드 배포로 안 바뀐다.
   [KAKAO-SETUP.md §5](KAKAO-SETUP.md) 의 새 문구로 교체해야 8번이 끝난다.
2. **단톡방 체크리스트** — [KAKAO-SETUP.md §6](KAKAO-SETUP.md) 에 이번 수정분
   5개를 추가해뒀다. 배포 후 직접 쳐본다.
3. **1번 재현 여부** — 죽은 링크를 버리고 빈손에 출구를 뒀으므로 증상은 완화된다.
   그래도 "다른 지역이 뜬다" 가 남으면 그건 **애드픽 변환이 딥링크를 버리는 것**이고,
   우리 코드로는 못 고친다. 그때는 `원본 → 애드픽 링크 → 최종 도착지` 를 따라가 확인한다.

### 나중에

- **클룩·트립닷컴 도시 ID 대조표** — 빈손 출구의 줄을 넷으로 늘린다.
  세부 지역까지는 ID 를 못 구해서 호텔스닷컴이 계속 주력이다.
- **10번** — 보류 지시. `notUnderstoodCard` 의 나머지 출구(여행 외 / 없는 지역명) 분리와
  "아래 예시를 참고해" 문구 수정이 남아 있다.
- **호텔 예산 반영** — 가격 필터가 걸린 주소를 받으면 그때.
