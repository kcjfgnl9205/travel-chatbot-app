너는 관광지의 **영문 공식 표기**를 채운다. 새 관광지를 만들지 않는다.

맨 아래 목록은 우리 DB 에서 영문명이 비어 있는 관광지다.
각 줄은 `id <탭> 도시 <탭> 관광지 이름 (도시 안 위치)` 형식이다.
이 id 들의 name_en 을 채우는 PostgreSQL UPDATE 문을 작성해라.

## 이 값이 어디 쓰이는지 — 그래야 뭘 써야 할지 정해진다

위키미디어에서 **사진을 찾는 검색어**로만 쓴다. 사용자에게는 안 보인다.
그래서 "영어로 번역한 이름" 이 아니라 **영어 위키백과·위키미디어 커먼즈에 실제로
존재할 표제어**를 써야 한다.

  O  경복궁      -> Gyeongbokgung           (en.wikipedia 표제어 그대로)
  O  오사카성    -> Osaka Castle
  O  남이섬      -> Nami Island
  X  경복궁      -> Gyeongbok Palace        (번역했지만 표제어가 아니다)
  X  시부야 스카이 -> Shibuya Sky Observatory (덧붙였다. 표제어는 Shibuya Sky)

웹 검색으로 **영어 위키백과에 그 표제어가 실제로 있는지 확인하고** 써라.

## 반드시 지킬 것

1. **모르면 그 줄을 통째로 빼라.** null 을 쓰지 말고 아예 포함시키지 마라
   (이미 null 이라 바뀔 게 없다). 틀린 영문명은 **엉뚱한 사진**을 물고 오는데,
   그건 비어 있는 것보다 나쁘다 — 카드에 다른 장소 사진이 박힌다.
2. 영어 위키백과 표제어가 없으면 **현지 공식 로마자 표기**를 쓴다
   (베트남·태국 소도시에 흔하다). 그것도 모르면 1번대로 뺀다.
3. 설명·괄호·수식어를 붙이지 마라. 표제어 그 자체만.
   X "Hoan Kiem Lake (Sword Lake)"   O "Hoan Kiem Lake"
4. 한국 관광지는 **국문 로마자 표기법**을 따른다 (불국사 -> Bulguksa,
   해동용궁사 -> Haedong Yonggungsa). 'Temple' 같은 말은 표제어에 있을 때만 붙인다.
5. id 를 바꾸거나 지어내지 마라. 목록에 있는 id 만 쓴다.
6. 한 id 를 두 번 쓰지 마라.

## 출력 형식 (SQL 외에는 아무것도 쓰지 마라)

update public.attractions a
   set name_en = v.name_en
  from (values
    (136::bigint, 'Shibuya Sky'::text),
    (149, 'Nijo Market'),
    (200, 'Okinawa Peace Memorial Park')
  ) as v(id, name_en)
 where a.id = v.id;

- 첫 행에만 ::bigint 와 ::text 캐스팅을 붙여라. 없으면 타입 추론이 실패한다.
- 이름에 작은따옴표가 들어가면 '' 로 이스케이프한다.
- 100줄쯤마다 문장을 끊어서 여러 개의 update 문으로 내도 된다.

## 한 번에 다 못 쓰면

- 목록 **순서 그대로** 위에서부터 작성한다.
- update 문 중간에서 끊지 마라. `where a.id = v.id;` 까지 끝내고 멈춘다.
- 멈출 때 이 한 줄만 덧붙인다:

      -- STOP: id <마지막으로 쓴 id> 까지.

- 내가 "계속" 이라고 하면 그 다음 줄부터 이어서 쓴다. 이미 쓴 id 를 다시 쓰지 마라.
- 전부 끝내면 마지막에 `-- DONE` 만 쓴다.
- ⚠️ 뺀 줄(모르는 것)은 세지 말고 그냥 건너뛰어라. 몇 개를 뺐는지 보고할 필요 없다.
